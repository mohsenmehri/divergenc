# تعویض MAC با پورت اعلام‌شدهٔ شعبه — IP بدون تغییر

نسخهٔ SERVER — ۲۰۲۶-۱۰-۱۸ — `FAM-CLIENT-MAC-REPLACEMENT-20261018`

## استفاده

۱. در عملیات واقعی تجهیزات، شعبه/سوئیچ را انتخاب کنید. کنار هر سوئیچ «پورت اختیاری» وجود دارد؛ مثلاً `7` یعنی `Fa0/7`. برای هر شعبه پورت مستقل است.
۲. **پورت خالی:** همان مسیر قبلی بررسی/انتخاب/تأیید رفع Err-disabled اجرا می‌شود؛ تغییری در source binding یا ARP ACL نمی‌دهد. دکمهٔ «فقط وضعیت» نیز همیشه فقط وضعیت را می‌خواند، حتی اگر پورت وارد شده باشد.
۳. **پورت واردشده:** «بررسی پورت‌ها» فقط پیش‌بررسی تعویض MAC همان پورت را انجام می‌دهد. هنوز هیچ تنظیمی تغییر نکرده است.
۴. اگر IP کلاینت دستی است، تیک «IP دستی — همان IP، فقط MAC جدید» را فعال کنید. IP و MAC قبلی از **دقیقاً یک binding ثابت همان پورت در VLAN 100** خوانده می‌شوند؛ IP از شمارهٔ پورت یا IP مدیریتی سوئیچ حدس زده نمی‌شود. ورودی جدید IP نداریم.
۵. پیش‌نمایش سوئیچ، پورت، IP بدون تغییر و MAC قبلی را کنترل کنید. دکمهٔ «تأیید و تعویض MAC همین پورت» را بزنید و مجازبودن دستگاه جدید و صحت پورت اعلام‌شده را تأیید کنید. این تأیید اجازهٔ یادگیری MAC دستگاه متصل به همان پورت است؛ اثبات هویت فیزیکی از روی MAC ممکن نیست.
۶. فقط همان دستگاه مجاز به پورت متصل باشد و ترافیک تولید کند. عملیات می‌تواند چند قطع ارتباط ایجاد کند. هر درخواست تعویض فقط یک پورت را تغییر می‌دهد؛ به‌صورت خودکار همهٔ شعب یا همهٔ پورت‌ها اجرا نمی‌شوند.

## توالی واقعی

- مدل/IOS با پروفایل محدود کلاسیک `WS-C2960-24TT-L` تطبیق داده می‌شود؛ فقط access تک‌کلاینت VLAN 100 و `Fa0/1` تا `Fa0/24`. Trunk، voice، port-channel، احراز هویت 802.1X و تعداد مجاز MAC بیش از یک، خارج از این مسیر هستند.
- قبل از اعمال، تنظیمات دوباره خوانده و با fingerprint پیش‌نمایش مقایسه می‌شوند. تأیید ۳۰۰ ثانیه‌ای، یک‌بارمصرف و وابسته به کاربر، حساب SSH، سوئیچ، پورت، تیک دستی و fingerprint است. موجودی و scope و مجوزهای بررسی و تعمیر دوباره کنترل می‌شوند.
- پورت ابتدا `shutdown` می‌شود؛ سپس `no ip verify source` اجرا می‌شود. این صورتِ حذفِ دستور فعال `ip verify source port-security` است.
- **فقط با تیک دستی:** binding قبلی و دقیقاً permit متناظر IP/MAC قدیمی از `arp access-list Inspection` حذف می‌شوند. کل ACL یا bindingهای دیگر حذف نمی‌شوند. پورت هنوز بسته است و نتیجهٔ حذف بررسی می‌شود.
- پورت باز می‌شود. رخ‌دادن Err-disabled فرض نمی‌شود؛ اگر واقعاً رخ دهد، حداکثر یک رفع محدود همان پورت انجام می‌شود. در خطای تکراری، ادامه متوقف می‌شود.
- تا چهار نوبت خواندن محدود برای مشاهدهٔ دقیقاً یک MAC جدید مشترک در CAM و secure-address همان پورت انجام می‌شود؛ فاصلهٔ نوبت‌ها دو ثانیه است. MAC قبلی، چند MAC، آدرس multicast/broadcast، تضاد binding یا secure MAC روی پورت دیگر پذیرفته نمی‌شود. هیچ MAC دلخواهی از مرورگر/کاربر به فرمان تزریق نمی‌شود.
- پورت برای بازگرداندن حفاظت دوباره بسته می‌شود. با تیک دستی، **همان IP و پورت** با MAC جدید در source binding و permit جدید `Inspection` قرار می‌گیرند. سپس `ip verify source port-security` فعال می‌شود. بدون تیک دستی، هیچ فرمان تغییر source binding یا ARP ACL صادر نمی‌شود.
- حفاظت و رکوردها در حالت بسته بررسی می‌شوند؛ سپس پورت باز و وضعیت لینک و CAM بررسی می‌شود. فقط پس از عبور از این بررسی‌ها نتیجهٔ تعویض اعلام می‌شود. این آزمون، ping یا دسترسی IP سرتاسری کلاینت نیست.

### مثال آموزشی، نه مقادیر ثابت برنامه

اگر binding قبلی `0001.08f1.31a6 / 10.4.86.7 / Fa0/7` و MAC جدید مشاهده‌شده `0002.2222.2222` باشد، حذف محدود به این رکوردهاست:

```text
no ip source binding 0001.08f1.31a6 vlan 100 10.4.86.7 interface Fa0/7
arp access-list Inspection
 no permit ip host 10.4.86.7 mac host 0001.08f1.31a6
```

و ساخت مجدد با IP بدون تغییر:

```text
ip source binding 0002.2222.2222 vlan 100 10.4.86.7 interface Fa0/7
arp access-list Inspection
 permit ip host 10.4.86.7 mac host 0002.2222.2222
```

این قطعه‌ها شرح عملیات‌اند، نه اسکریپت کامل قابل اجرای مستقل؛ مدیریت context و shutdown/بررسی/بازگرداندن IPSG در helper انجام می‌شود.

## توقف‌های مهم و محدودیت عملیاتی

- **Sticky/Configured قبلی:** مجوز حذف آن داده نشده؛ پیش‌بررسی قبل از تغییر متوقف می‌شود. هیچ `clear` کلی یا پاک‌کردن Sticky خودکار اضافه نشده است. اگر سیاست شعب شما برای تعویض نیازمند حذف محدود Sticky است، آن مجوز و طراحی باید جداگانه تعیین شود. این نسخه جایگزین آن تصمیم نیست.
- نبود binding ثابت/permit متناظر، چند binding روی پورت، چند MAC، پورت مدیریتی بسته، ACL پیچیده با deny/remark یا نحو غیرپشتیبانی‌شده: توقف پیش از تغییر، نه انتخاب اولین رکورد.
- binding ثابت روی پورت بدون تیک دستی نیز پذیرفته نمی‌شود؛ برای جلوگیری از باقی‌ماندن مجوز قدیمی، تیک صحیح و بررسی مجدد لازم است. DHCP-snooping ثابت نیست و به‌صورت دستی پاک/بازنویسی نمی‌شود.
- از تغییر هم‌زمان تنظیمات همان سوئیچ توسط ابزارهای دیگر خودداری کنید. قفل FAM فقط درخواست‌های خود FAM را هماهنگ می‌کند.
- شکست پس از احتمال شروع تغییر: یک تلاش جبرانی محدود برای **shutdown همان پورت، بازگرداندن policy قدیمیِ شناخته‌شده و فعال‌کردن IPSG** انجام می‌شود؛ هرگز `no shutdown` جبرانی نداریم. اگر بسته‌بودن و IPSG تأیید شوند، وضعیت «نیازمند بررسی کارشناس / قرنطینه» اعلام می‌شود، نه موفقیت. بازیابی کامل پیکربندی قبلی یا رفع خطا تضمین نمی‌شود.
- اگر SSH قطع شود/دستورها کامل تأیید نشوند، حتی بسته‌بودن پورت یا فعال‌بودن حفاظت ممکن است معلوم نباشد. پیام **وضعیت نامشخص؛ بررسی فوری همان پورت** نمایش داده می‌شود. درخواست را تکرار نکنید؛ کارشناس مجاز باید خود پورت، IPSG و binding/ACL را کنترل کند. ارتباط مدیریتی از مسیری مستقل از پورت هدف لازم است.
- زمان helper: پیش‌بررسی ۷۰ ثانیه، اعمال حداکثر ۱۵۰ ثانیه (بودجهٔ فعال ۱۱۵ ثانیه و بقیه برای حفاظت جبرانی)؛ executor به‌ترتیب ۸۰/۱۶۰ و مرورگر ۹۰/۱۷۰ ثانیه. lease مشترک ۱۸۰ ثانیه است. خروج از صفحه، logout یا timeout مرورگر الزاماً عملیات ارسال‌شده به سوئیچ را لغو نمی‌کند.
- عملیات فقط running-config را تغییر می‌دهد؛ `enable`، `write memory`، `copy running-config`، ذخیرهٔ تنظیمات، debug و فرمان آزاد وجود ندارد. ماندگاری پس از reboot جزء این پچ نیست.

## نصب و پذیرش

از **کل ZIP SERVER همین نسخه** با ۲۲ فایل payload و updater همراه آن استفاده کنید؛ فایل `equipment_replacement.py` ضروری است. راهنمای نصب/backup/rollback در `README_FA.txt` است. از updater و backup همان نسخه استفاده کنید؛ DB یا اطلاعات تجهیزات حذف/بازنشانی نمی‌شوند. کلاینت LOCAL عملیات SSH/تعویض واقعی ندارد.

این نسخه با transcriptهای مصنوعی و فرایند SSH ساختگی و مرورگر تست می‌شود؛ روی سوئیچ واقعی، RADIUS واقعی، Windows/IIS اجرا و پذیرش نشده است. پیش از rollout شعب، در محیط تست با IOS و تنظیمات واقعیِ بدون اطلاعات حساس، حالت موفق، نداشتن ترافیک، Sticky قبلی و قطع SSH را بررسی کنید. هیچ رمز یا کانفیگ کامل را در چت ارسال نکنید.
