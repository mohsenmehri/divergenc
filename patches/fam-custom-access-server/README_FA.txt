به‌روزرسانی مدیریت کاربران و دسترسی‌های سفارشی + مدیریت تجهیزات — سرور مرکزی / IIS

این پچ برای نصب مرکزی FAM در C:\FAM و C:\FAMData است. رابط مدیریت کاربران را با نسخهٔ محلی یکسان می‌کند: محدودهٔ دسته‌ها، زیرمحدودهٔ مناطق برای استان‌ها، و مجوزهای ریزعملیاتی. «سطح کاربر» در فرم نمایش داده نمی‌شود.

مسیر SSH قبلی صفحهٔ مستقل عملیات شبکه و Worker Token را حذف می‌کند و تب «تجهیزات» را داخل صفحهٔ اصلی FAM اضافه می‌کند. اتصال SSH مستقیماً از خود سرور FAM (10.16.243.18) به تجهیز انجام می‌شود؛ VDI Connector، Worker، Token، Pairing، سرویس ویندوز یا ذخیرهٔ credential وجود ندارد. به‌جای Netmiko/Paramiko از Windows OpenSSH (ssh.exe) با استثنای موقت و محدود `-o Ciphers=+aes128-cbc` استفاده می‌شود (3des-cbc، aes192-cbc و aes256-cbc فعال نمی‌شوند). کاربر مجاز IP خصوصی تجهیز و نام کاربری/رمز موقت SSH یا RADIUS را وارد می‌کند؛ رمز فقط در RAM همان درخواست و environment همان child process ssh.exe است و هرگز در command-line، فایل، دیتابیس یا log قرار نمی‌گیرد. عملیات status فقط `terminal length 0` / `show interfaces status` / `exit` است و اگر پورت err-disabled وجود نداشته باشد پیام «وضعیت پاک» نمایش داده می‌شود. برای رفع، کاربر همان پورت را تأیید می‌کند؛ سرور pre-check، `shutdown` / `no shutdown` محدود روی همان Interface و post-check انجام می‌دهد. command آزاد، Enable، ذخیرهٔ تنظیمات وجود ندارد. Host key با فایل اختصاصی C:\FAMData\equipment\known_hosts و سیاست accept-new بررسی می‌شود (StrictHostKeyChecking=no استفاده نمی‌شود).

پیش‌نیاز: «OpenSSH Client» ویندوز روی سرور FAM نصب باشد (C:\Windows\System32\OpenSSH\ssh.exe) و `ssh -Q cipher` شامل aes128-cbc باشد. نصاب این را پیش از هر تغییر بررسی می‌کند. .NET Framework 4.x و compiler داخلی csc.exe برای ساخت ASKPASS موقت لازم است؛ هیچ wheel یا بستهٔ Python نصب نمی‌شود. ASKPASS یک exe موقت بدون رمز است که فقط از environment فرزند می‌خواند؛ source و exe در finally حذف می‌شوند.

روش اجرا
1) ZIP Patch را روی خود سرور Extract کنید.
2) APPLY-CUSTOM-ACCESS-UPDATE.cmd را با Run as administrator اجرا کنید.
3) فقط پیام سبز `CUSTOM ACCESS + PRIVATE FAM UI UPDATE APPLIED.` معتبر است. سپس FAM را refresh کنید و تب «تجهیزات» را باز کنید.

ایمنی و بازگشت
- پیش از تغییر، app.py، equipment_inventory.py، equipment_ops.py، equipment_probe.py، start.ps1، FAM.html، login.* و web.config فعلی زیر C:\FAMData\backups\custom-access-<date> ذخیره می‌شوند و فقط همین فایل‌ها جایگزین می‌شوند.
- اگر فایلی قبلاً وجود نداشته و Patch ناموفق شود، خودکار حذف و بقیه از backup بازگردانده می‌شوند.
- Patch هیچ رمز، Token، دیتابیس، PFX، private key، log یا venv همراه ندارد؛ صحت payload با SHA256SUMS.txt پیش از هر تغییر بررسی می‌شود.
- وظیفهٔ شناخته‌شدهٔ FAM-Central کنترل‌شده متوقف و پس از جایگزینی، شنود پورت داخلی 8765 بررسی می‌شود.
- پچ هیچ فایل SQLite، worksheet، داده، نام worksheet، رمز یا رکورد کاربر را پاک/جابه‌جا نمی‌کند.

مهاجرت حساب‌ها
در راه‌اندازی، ستون‌های nullable categories و permissions به جدول users اضافه می‌شوند. حساب‌های قدیمی نقش‌محور تا نخستین ذخیره از ویرایشگر جدید سازگار می‌مانند. پس از ذخیره، مجوزهای ریز و محدوده‌ها روی سرور، نه فقط رابط مرورگر، اجرا می‌شوند.

این revision علاوه بر custom access، hardening کم‌ریسک سرور را نیز دارد: HSTS یک‌ساله، خواندن fail-closed دادهٔ JSON کاربران، رد صریح شیت سیستمی غیرمجاز و allowlist نصب کامل.

بعد از اجرا، صفحه را دوباره باز کنید. FAM با no-cache پاسخ می‌دهد؛ پاک‌کردن دستی cache لازم نیست.


انتشار مرکزی تجهیزات — 2026-10-17
- آخرین موجودی، دسته‌ها، کارت‌ها و استانداردهای نسخهٔ LOCAL به رابط مرکزی منتقل شده‌اند. این داده‌های بدون رمز در جدول equipment_state همان SQLite سرور نگه‌داری می‌شوند؛ از browser storage برای نگه‌داری تجهیزات استفاده نمی‌شود. اطلاعات LOCAL قبلی خودکار از مرورگر به سرور کپی نمی‌شود.
- مجوزهای جداگانه افزودن/ویرایش/حذف، دسته‌ها، کارت‌ها، ورود/خروج اکسل، پیکربندی، استاندارد، تطبیق، بررسی و رفع، همراه پنج محدودهٔ نوع/مدل/منطقه/نوع محل/محل، در مدیریت کاربران قابل تنظیم‌اند. همهٔ ابعاد با «و» ترکیب می‌شوند؛ * یعنی همهٔ فعلی و آینده، انتخاب خالی یعنی هیچ. نام‌ها از دسته‌های جاری می‌آیند و شناسه‌های حذف‌شده دسترسی نمی‌دهند.
- سرور نشست و محدوده را دوباره بررسی می‌کند؛ تغییر حساب نشست قبلی را بی‌اعتبار می‌کند. رکوردهای مخفی هنگام ثبت کاربر محدود حفظ می‌شوند. برخورد IP و وابستگی‌های مخفی مانع ثبت‌اند. استاندارد وابسته را پیش از حذف دستهٔ آن حذف/اصلاح کنید.
- ثبت با نسخهٔ مرکزی انجام می‌شود. تا تأیید سرور ویرایش مسدود است؛ قطع ارتباط/تعارض، موفقیت فرض نمی‌شود و تکرار/بازنویسی خودکار ندارد. وضعیت قطعی را دریافت و تغییر را دوباره بازبینی کنید.
- ورودی اکسل و فهرست‌های Stop وابسته از دسته‌های فعلی ساخته می‌شوند. پس از تغییر دسته‌ها، فرم تازه بگیرید؛ importer مرورگر ساختار/نسخهٔ فرم را بررسی می‌کند و سرور مستقل، داده‌ها/مجوزها/محدوده/وابستگی/IP را اعتبارسنجی می‌کند.
- پیکربندی و تطبیق کانفیگ همچنان آفلاین/نمایشی و RAM-only هستند. مسیر بررسی Err-disabled اکنون یک مسیر ساده و واقعی در «ابزارها» و صفحهٔ نود است: انتخاب سوئیچ‌ها، بررسی پورت‌ها، نمایش نام/IP سوئیچ کنار پورت، سپس تأیید رفع. سناریوهای ساختگی و فرم جداگانهٔ قدیمی از SERVER حذف شده‌اند. حداکثر ۵ سوئیچ/۵ پورت در هر نوبت، یکی‌یکی با همان API و helper محدود قبلی انجام می‌شوند؛ صف دائمی، Worker یا فرمان آزاد اضافه نشده است. بررسی واقعی نیازمند equipment-scan، رفع واقعی نیازمند equipment-repair و هر دو نیازمند محدودهٔ مجاز تجهیز هستند. حساب دارای همهٔ پنج محدودهٔ * مسیر IP خصوصی قبلی را حفظ می‌کند؛ حساب محدود فقط IP موجود در موجودی مجاز را می‌تواند هدف بگیرد.
- در نسخهٔ مرکزی ورود FAM کافی است؛ فرم RADIUS نمایشی LOCAL نشان داده نمی‌شود. نام کاربری و رمز واقعی سوئیچ را فقط در فرم سادهٔ ابزارها وارد کنید؛ تا خروج از FAM در حافظهٔ همان صفحه باقی می‌مانند و با refresh پاک می‌شوند. روی سرور فقط برای درخواست جاری مصرف می‌شوند؛ نه در موجودی، نه تنظیمات مرورگر و نه فایل ذخیره نمی‌شوند.
- پاک‌سازی فهرست تاریخچه با مجوز مستقل و تأیید صریح روی سرور انجام و برای نشست‌های دیگر نیز همگام می‌شود. این کار فهرست را پاک می‌کند؛ نسخه‌های داخلی لازم برای بازگشت، طبق نگه‌داری سیستم باقی می‌مانند. داده‌ها و حساب‌ها حذف نمی‌شوند.
- مهاجرت افزایشی ستون equipment_scope و history_floor و جدول equipment_state انجام می‌شود؛ SQLite/حساب موجود از نو ساخته نمی‌شود. backup کد توسط Patch جایگزین backup مستقل دیتابیس نیست؛ قبل از نصب از دیتابیس زنده با روش backup تأییدشدهٔ FAM نسخه بگیرید و آن را ارسال نکنید.
- تست خودکار Linux/مرورگر انجام شده؛ نصب Windows/IIS و ارتباط با تجهیز واقعی در این محیط آزمایش نشده است. ابتدا روی کپی محیط سرور تست کنید.

نتیجهٔ انتشار قبلی مرکزی: مجموعهٔ بک‌اند ۱۰۷ مورد (۱۰۶ موفق، یک مورد محیطی skip)، ۵۶ تست مدل/ساخت JavaScript موفق، و تست واقعی مرورگر با دو نشست مستقل، بازگشایی، همگامی تاریخچه، حفظ پیش‌نویس محدودهٔ کاربر و توقف در ثبت معلق/تعارض موفق بود؛ صفر خطای uncaught. تست نصب Windows/IIS و اتصال واقعی تجهیز اجرا نشده است.


اصلاح مسیر سادهٔ واقعی بررسی پورت‌ها:
- «ابزارها» را باز کنید؛ سوئیچ‌ها را از موجودی مجاز انتخاب و حساب SSH / RADIUS مشترک آن‌ها را وارد کنید. دیگر سناریوی نمایشی انتخاب نمی‌شود. برای حساب‌های متفاوت در دو نوبت جدا بررسی کنید.
- هر ردیف نام و IP سوئیچ را دارد. فقط بررسی تأییدشدهٔ SSH و جدول معتبر می‌تواند «پورت Err-disabled یافت نشد» بدهد. احراز هویت ناموفق، timeout، پاسخ ناقص و جدول نیمه‌خوانده‌شده همیشه ناموفق/نامشخص‌اند.
- حالت‌های صریح err-disabled / errdisable / errdisabled تشخیص داده می‌شوند. پورت disabled، notconnect و connected خطا محسوب نمی‌شود. پورت هدف باید در pre-check و post-check وجود داشته باشد؛ ناپدیدشدن آن موفقیت رفع نیست.
- پورت‌ها را انتخاب کنید؛ نام/IP/پورت دقیق را در پنجرهٔ تأیید ببینید. انصراف هیچ فرمان رفعی ارسال نمی‌کند. پس از تأیید، فقط همان پورت pre-check، shutdown / no shutdown و post-check می‌شود. Enable، write memory و copy running-config ممنوع و غیرفعال‌اند.
- اگر تأیید کوتاه‌مدت پورت منقضی شد، یا نتیجهٔ رفع تأیید نشد، دوباره بررسی کنید؛ تکرار خودکار وجود ندارد. خروج از بخش هنگام اجرای درخواست نمی‌تواند اجرای از قبل ارسال‌شده را تضمیناً لغو کند؛ قبل از اقدام بعدی وضعیت را دوباره بررسی کنید.
- آزمون جدید مرورگر با سه سوئیچ ساختگی و API احرازهویت‌شده موفق بود: خطادار/پاک/timeout جدا، مالکیت هر پورت، انصراف بدون درخواست، دقیقاً یک رفع تأییدشده، پاسخ ناقص به‌عنوان نامشخص، ماندگاری RAM در جابه‌جایی و پاک‌شدن پس از refresh؛ صفر خطای uncaught. executor در این آزمون ساختگی است؛ هیچ سوئیچ واقعی تماس گرفته نشده است. نصب Windows/IIS و وضعیت سوئیچ شما هنوز باید در محیط تست خودتان تأیید شود.

نتیجهٔ نهایی این اصلاح: ۱۱۲ مورد بک‌اند، ۱۱۱ موفق و یک مورد محیطی skip؛ ۵۷ تست مدل/ساخت JavaScript موفق؛ هر دو تست مرورگر مرکزی و مسیر سادهٔ SSH موفق با صفر خطای uncaught. آزمون SSH با executor ساختگی و تست parser با child process ساختگی اجرا شد، نه اتصال واقعی شبکه.


IP دستی و show int des — نسخهٔ سرور
- در تجهیزات ← ابزارها نام کاربری و رمز SSH / RADIUS سوئیچ را وارد کنید؛ یا سوئیچ‌های ثبت‌شده را انتخاب کنید، یا IP خصوصی را در «بررسی و رفع خطا با IP دستی» بزنید. دکمهٔ بررسی IP دستی، بررسی واقعی از سرور را انجام می‌دهد؛ رمز و IP دستی ذخیره نمی‌شوند.
- IP دستیِ خارج از موجودی فقط برای حساب دارای * در هر پنج بُعد مجاز است. حساب محدود فقط IP ثبت‌شده در موجودی مجاز خودش را می‌تواند بررسی کند؛ تغییر روش ورود یا واردکردن IP دستی محدوده را دور نمی‌زند.
- بعد از بررسی موفق، سرور خروجی دستور ثابت show interfaces description (همان show int des) را نیز می‌خواند؛ دکمهٔ مستقل «نمایش خروجی show int des» بدون تغییر پورت هم وجود دارد.
- جدول خروجی با همان سطرها و فاصله‌ها نمایش داده می‌شود. بنر/prompt/خطاهای داخلی و خروجی دستورهای دیگر نمایش داده نمی‌شوند؛ متن حساس در توضیحات با [REDACTED] پوشانده می‌شود. این محدودیت ایمنی است، نه اجرای command آزاد.
- خروجی فقط RAM است؛ در موجودی، workbook، history، browser storage و فایل ذخیره نمی‌شود. خطای خواندن خروجی جدا از نتیجهٔ بررسی پورت گزارش می‌شود. خطای اتصال/احراز هویت/جدول ناقص هرگز «بدون خطا» نیست.
- رفع واقعی همچنان فقط پس از مشاهدهٔ نام/IP/پورت و تأیید صریح، همراه pre-check و post-check همان پورت است. Enable، فرمان آزاد و ذخیرهٔ کانفیگ وجود ندارد.
- آزمون‌های helper با child process ساختگی و مرورگر با API واقعی و executor ساختگی انجام شده‌اند؛ Windows/IIS و ارتباط با سوئیچ واقعی اینجا آزمایش نشده‌اند. روی کپی محیط تست نصب و بعد از بکاپ از دیتابیس اقدام کنید.

اعتبارسنجی اصلاح IP دستی/show int des: مجموعهٔ بک‌اند ۱۱۷ مورد، ۱۱۶ موفق و یک مورد محیطی skip؛ ۵۸ تست JavaScript موفق. تست مرورگر مسیر واقعی UI/API با executor ساختگی، IP دستی، تأیید رفع و نمایش امن خروجی موفق و صفر خطای uncaught بود؛ نه اتصال واقعی به تجهیز.
