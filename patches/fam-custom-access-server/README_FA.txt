# پچ اصلاحات SERVER — راهنمای نصب، پذیرش و بازگشت

تاریخ آخرین به‌روزرسانی: ۲۰۲۶-۱۰-۱۸ — این پچ **اصلاح واقعی کد** است، نه ZIP بررسی قبلی.

بسته: `releases/FAM-Custom-Access-SERVER-Patch.zip`، همراه فایل `.zip.sha256`.
راهنمای داخل ZIP: `README_FA.txt`. مخصوص **نصب موجود مرکزی Python/IIS** است؛ نصب مستقل، LOCAL یا پروژه‌های جایگزین نیست.

## چه چیزهایی اصلاح شد؟

| یافتهٔ تأییدشده | اصلاح |
| --- | --- |
| F01، رمز شناخته‌شدهٔ bootstrap | نصب تازه بدون رمز اولیهٔ ۱۲ تا ۱۲۸ نویسه‌ای متوقف می‌شود؛ ابزار bootstrap ورودی مخفی کنسول دارد و fallback با ورودی آشکار ندارد. حساب‌های موجود تغییر نمی‌کنند. رمز جدید تولیدی نیز حداقل ۱۲ نویسه لازم دارد؛ ورود با hash قبلی سازگار است. |
| F02، اثر نامشخص رفع و ادامهٔ دسته | شکست/قطع پس از احتمال شروع تغییر، `recovery_uncertain` است؛ UI بقیهٔ دسته را متوقف و تأییدهای باقی‌مانده را نامعتبر می‌کند. باقی‌ماندن err-disabled هم دسته را متوقف می‌کند. هیچ retry، no-shutdown جبرانی یا Enable خودکار اضافه نشده است. |
| F03، تکرار تأیید | هر ticket nonce تصادفی دارد و مصرف آن به‌صورت اتمیک ثبت می‌شود. تکرار همان تأیید رد می‌شود؛ restart می‌تواند تأییدهای قبلی را نامعتبر کند و بررسی تازه لازم شود. |
| F04، هم‌زمانی | قفل مشترک SQLite، حداکثر یک درخواست SSH برای هر IP و دو درخواست برای کل سرور؛ در فرایندهای مستقل هم اعمال می‌شود. وضعیت مشغول باعث مصرف ticket منتظر نمی‌شود. |
| F05، مدیر سفارشی و backup | runtime، manage و preflight از سیاست مشترک مدیر فعال استفاده می‌کنند؛ داشتن مجوز واقعی manage-users در حساب سفارشی پذیرفته می‌شود. ردیف خراب/غیرفعال مدیر محسوب نمی‌شود. |
| F06، پوشاندن متن حساس | بررسی متن اصلی Name قبل از کوتاه‌سازی، بدون حساسیت به بزرگی حروف و با تشخیص عبارت‌های حساس مشترک با جدول توضیحات. این فیلتر تضمین تشخیص هر راز ناشناخته یا ازقبل‌بریده‌شده در خود تجهیز نیست. |
| F07، تفاوت Router/Switch | تجهیز موجودی که روتر شناخته شده است، حتی برای wildcard در API بررسی/رفع switch-only رد می‌شود. |
| F08، host key | پیش‌فرض app/helper/start برابر strict؛ مقدار صریح معتبر startup دیگر بی‌قید بازنویسی نمی‌شود. accept-new همچنان فقط TOFU است و معادل strict نیست. |
| F09، مستندات اتصال | مسیر فعلی مستند شده: سرور FAM مستقیم به تجهیز؛ بدون Connector/VDI/Worker/Pairing. |

اصلاحات مرتبط: گزینهٔ مستقل «فقط وضعیت» بدون وابستگی به جدول توضیحات؛ حفظ مسیر اصلی inspect؛ محیط حداقلی فرزند بدون bootstrap/signing secret سرور؛ نظارت Job Object ویندوز و توقف fail-closed در شکست آن؛ بازنشسته‌کردن idempotent فایل عمومی قدیمی FAM.html؛ backup و rollback کد با manifest حضور و hash.

محدوده ثابت مانده است: IPهای RFC1918 و RFC6598 از جمله 100.100.1.22 / 100.108.1.22 / 100.107.1.22 مجازند، نه IP عمومی دلخواه. مجوز عملیات و هر پنج scope مستقل اعمال می‌شوند. هیچ CLI آزاد، Enable، write memory، copy running-config یا ذخیرهٔ credential اضافه نشده است. فقط استثنای محدود aes128-cbc حفظ شده است.

## ۱. پیش‌نیاز و توقف امن

- ابتدا روی **کپی خصوصی محیط تست**، با همان نسخه و ساختار نصب، امتحان کنید. همسانی نسخهٔ سرور واقعی با این مخزن هنوز احراز نشده است.
- پنجرهٔ نگهداری تعیین کنید؛ هیچ بررسی/رفع جاری نباشد. خاتمهٔ درخواست ارسالی ثابت نمی‌کند فرمان روی تجهیز اجرا نشده؛ در تردید اپراتور مجاز باید وضعیت را بررسی کند.
- دسترسی Administrator به خود سرور، Windows PowerShell 5.1، محیط Python نصب‌شدهٔ FAM و وابستگی‌های موجود لازم است. این ZIP اینترنت، wheel یا وابستگی تازه نصب نمی‌کند.
- Windows OpenSSH Client با پشتیبانی aes128-cbc و .NET Framework 4.x/csc.exe لازم‌اند.
- مسیر پیش‌فرض کد `C:\FAM\server` و داده `C:\FAMData` است. settings.json، پایگاه موجود و Scheduled Task شناخته‌شدهٔ FAM-Central باید وجود داشته باشند. اگر task غیرفعال است، ابتدا علت را بررسی کنید؛ پچ آن را خودسرانه راه‌اندازی نمی‌کند.
- DB را در پوشهٔ عمومی IIS نگذارید. از داده و کد، نسخهٔ پشتیبان مستقل و محافظت‌شده خارج از سرور نیز داشته باشید. SQLite زنده را با Explorer کپی نکنید.
- برای نصب پچ هیچ DB، settings، known_hosts، venv یا حسابی را حذف/از نو نسازید. installer کامل را به‌جای updater اجرا نکنید.

## ۲. بررسی بسته و نصب

ZIP و فایل checksum را از همین خروجی بگیرید. در PowerShell:

```powershell
Get-FileHash .\FAM-Custom-Access-SERVER-Patch.zip -Algorithm SHA256
Get-Content .\FAM-Custom-Access-SERVER-Patch.zip.sha256
```

مقادیر باید برابر باشند. hash جای امضای ناشر را نمی‌گیرد؛ هر دو فایل را از منبع مورد اعتماد بگیرید. ZIP را کامل در پوشهٔ خصوصی خارج از www استخراج کنید؛ فایل‌های payload را دستی مخلوط نکنید.

برای مسیرهای پیش‌فرض، `APPLY-CUSTOM-ACCESS-UPDATE.cmd` را Run as administrator اجرا کنید. برای مسیر سفارشی، از PowerShell مدیریتی داخل پوشهٔ استخراج‌شده:

```powershell
.\APPLY-CUSTOM-ACCESS-UPDATE.ps1 -InstallRoot 'C:\FAM' -DataDir 'C:\FAMData'
```

ترتیب updater:

۱. allowlist ۲۱ فایل و SHA256 هر payload، DB/settings و task و OpenSSH/compiler بررسی می‌شوند؛ bootstrap در این مسیر ممنوع است.
۲. پوشهٔ backup با ACL فقط SYSTEM/Administrators ایجاد می‌شود. task مرکزی هنگام تعویض غیرفعال/متوقف و بسته‌شدن پورت 8765 بررسی می‌شود؛ task backup روزانه موقتاً متوقف/غیرفعال می‌شود.
۳. **preflight اصلاح‌شدهٔ داخل payload** با SQLite backup API، snapshot سازگار می‌گیرد و سلامت و وجود مدیر فعال را بررسی می‌کند؛ پیش از تعویض کد. نسخهٔ قدیمی preflight که مدیر سفارشی را رد می‌کرد اجرا نمی‌شود.
۴. کد موجود، حضور/نبود هر فایل و hash آن ثبت می‌شود؛ فقط ۲۱ فایل مجاز جایگزین می‌شوند و FAM.html قدیمیِ عمومی حذف می‌شود. اجرای دوباره نیازمند وجود آن فایل قدیمی نیست.
۵. UI خصوصی ACL محدود می‌گیرد؛ task مرکزی فعال/شروع، شنود داخلی بررسی و task backup در صورت فعال‌بودن قبلی دوباره فعال می‌شود.

پیام موفقیت دقیق:

```text
SERVER SECURITY + RECOVERY FIX APPLIED.
```

مسیر `Private backup:` را یادداشت کنید؛ مثلاً `C:\FAMData\backups\custom-access-<timestamp>-<suffix>`.
شنود پورت فقط بررسی شروع backend است، نه اثبات سلامت کامل IIS یا عملکرد تجهیزات؛ چک‌های بخش ۴ الزامی‌اند.

دادهٔ موجود، تنظیمات، حساب‌ها و scopeها بازنشانی نمی‌شوند. پچ عمداً رمز حساب موجود را تغییر نمی‌دهد؛ اگر در نصب قدیمی رمز پیش‌فرض/شناخته‌شده باقی مانده، مدیر مجاز باید آن را از UI به رمز یکتای قوی تغییر دهد، نه با reset یا حذف DB. تنها جدول‌های افزایشی موقت هماهنگی برای digest ticket و lease اضافه می‌شوند؛ credential، ticket کامل، نتیجه یا فرمان در آن‌ها ذخیره نمی‌شود. lease برابر ۱۸۰ ثانیه در برابر سقف ۹۵ ثانیهٔ helper است؛ پس از crash ممکن است تا انقضا درخواست جدید رد شود. از تغییر ساعت سرور حین کار خودداری کنید.

## ۳. کلید SSH پیش‌تأییدشده — قبل از بررسی تجهیز

فایل پیش‌فرض `C:\FAMData\equipment\known_hosts` است. فایل قبلی حذف نمی‌شود؛ وجود یک ورودی قدیمی به‌تنهایی ثابت نمی‌کند آن کلید مستقل تأیید شده است.

۱. fingerprint کلید تجهیز را از کنسول/مدیر تجهیز یا کانال مورد اعتماد مستقل بگیرید.
۲. کلید عمومی همان تجهیز را تهیه کنید. در صورت استفاده از ssh-keyscan، خروجی فعلاً **کاندیدِ غیرقابل اعتماد** است، نه مجوز اتصال. مثال صرفاً برای اجرای اپراتور روی تجهیز مجاز خودش:

```powershell
$Candidate = 'C:\FAMData\equipment\candidate-known-hosts.txt'
& "$env:SystemRoot\System32\OpenSSH\ssh-keyscan.exe" -T 5 100.100.1.22 2>$null |
    Set-Content -LiteralPath $Candidate -Encoding ascii
& "$env:SystemRoot\System32\OpenSSH\ssh-keygen.exe" -lf $Candidate
```

۳. نوع کلید و fingerprint هر ورودی را با منبع مستقل تطبیق دهید؛ فقط خطوط تأییدشده را به known_hosts اضافه کنید، با قالب استاندارد OpenSSH و IP مقصد واقعی. نتیجهٔ mismatch را نادیده نگیرید؛ فایل را برای رفع خطا خالی نکنید. در چرخش کلید فقط همان ورودی، پس از تأیید مستقل و با نگهداری backup خصوصی، جایگزین شود.
۴. LOCAL SERVICE باید به فایل دسترسی خواندن و به مسیر خصوصی runtime دسترسی لازم داشته باشد؛ IIS و کاربران عمومی نه. کلید عمومی را هم داخل ZIP پچ نفرستید.
۵. پیش‌فرض strict است. اگر پیش‌تر machine environment صریح accept-new داشته‌اید، برای سیاست مطلوب، در PowerShell مدیریتی تنظیم کنید و در پنجرهٔ نگهداری task را restart کنید:

```powershell
[Environment]::SetEnvironmentVariable('FAM_EQUIPMENT_HOST_KEY_POLICY','strict','Machine')
```

مقدار محیط فرایند Task Scheduler را هم در پذیرش بررسی کنید؛ inheritance متغیر machine در سرویسِ ازقبل‌فعال همیشه فوری نیست. start.ps1 مقدار صریح معتبر را حفظ می‌کند. در صورت لزوم راه‌اندازی مجدد برنامه‌ریزی‌شدهٔ سرور/سرویس میزبان را با مدیر ویندوز هماهنگ کنید. هرگز برای رفع خطا StrictHostKeyChecking=no، حذف known_hosts یا cipher ضعیف دیگر اضافه نکنید.

## ۴. پذیرش بعد از نصب

ابتدا بدون اتصال تجهیز:

- `Get-ScheduledTask -TaskName FAM-Central` و وضعیت task روزانه و لاگ خصوصی سرویس را بررسی کنید؛ لاگ را با credential یا محتوای DB عمومی نکنید.
- با HTTPS معتبر سازمان، صفحهٔ ورود و `/app` را باز کنید؛ خطای گواهی را دور نزنید. در پنجرهٔ ناشناس، فایل برنامه نباید بدون نشست به‌عنوان فایل استاتیک آزاد شود.
- در کنسول مرورگرِ صفحهٔ احرازشده، `document.querySelector('meta[name="fam-release"]').content` باید `FAM-EQUIPMENT-V2-SERVER-FIX-20261017` باشد. این marker مکمل بررسی hash است، نه اثبات تنهاییِ سلامت backend.
- با حساب موجود وارد شوید؛ تعداد/شناسهٔ تجهیزات، دسته‌بندی، اطلاعات، حساب‌ها و دسترسی‌ها را با قبل مقایسه کنید. نیازی به رمز اولیهٔ تازه برای نصب موجود نیست؛ اگر چنین خواسته‌ای دیدید توقف و مسیر DB را بررسی کنید.
- logout/login و refresh را امتحان کنید. credential تجهیز نباید پس از refresh باقی بماند؛ صرف تغییر تب نباید آن را پاک کند.
- از مسیر مجاز UI یا backup روزانه، backup تأییدشده بگیرید؛ مدیر سفارشی فعال هم باید معتبر باشد. خروجی‌ها حساس‌اند و فقط خصوصی نگهداری شوند.

فقط سپس با مجوز جداگانهٔ مدیر شبکه، روی سوئیچ آزمایشی و پورت مجاز:

- بررسی اصلی یک درخواست inspect می‌فرستد؛ خطای SSH یا جدول ناقص نباید «سالم» نشان داده شود. دکمهٔ «فقط وضعیت» بدون وابستگی به descriptions کار می‌کند.
- خطای کلید ناشناخته/تغییریافته باید اتصال را رد کند؛ برای آزمایش، trust واقعی را تخریب نکنید.
- رفع فقط روی پورت err-disabled گزارش‌شده، پس از تأیید دقیق نام/IP/interface و pre-check/post-check مجاز است؛ انصراف نباید درخواست رفع بفرستد.
- شکست یا نتیجهٔ نامشخص باید ادامهٔ دسته را متوقف کند؛ پورت‌های اجرا‌نشده به بررسی تازه نیاز دارند. تأیید قبلی قابل استفادهٔ مجدد نیست.

**در recovery_uncertain:** هیچ رفع خودکار دیگری نزنید؛ ممکن است shutdown به تجهیز رسیده باشد ولی no shutdown یا post-check تأیید نشده باشد. ابتدا وضعیت همان interface را با اپراتور مجاز بررسی کنید. برنامه پورت administratively disabled را خودکار فعال نمی‌کند. کلیک مجدد جای تشخیص علت یا مجوز تغییر نیست.

## ۵. بازگشت کد بدون ازبین‌بردن داده

در شکست بعد از شروع کپی، updater تلاش می‌کند کد قبلی را برگرداند؛ DB را عقب نمی‌برد. پیام خطا یا rollback ناموفق به معنی نصب موفق نیست. در شکست بازگشت، task ممکن است متوقف/غیرفعال بماند؛ ابتدا وضعیت سرویس و backup را بررسی کنید، نه نصب دوباره یا حذف DB.

برای بازگشت دستی، همان بسته و پوشهٔ backup چاپ‌شده را نگه دارید. از PowerShell مدیریتی:

```powershell
.\ROLLBACK-CUSTOM-ACCESS-UPDATE.ps1 `
  -InstallRoot 'C:\FAM' -DataDir 'C:\FAMData' `
  -BackupDirectory 'C:\FAMData\backups\custom-access-<exact-saved-name>'
```

یا `ROLLBACK-CUSTOM-ACCESS-UPDATE.cmd` را مدیریتی اجرا و مسیر دقیق را وارد کنید. مسیر نمونه را عیناً اجرا نکنید. backup باید زیر backups خصوصی باشد؛ حضور و hash کد بررسی می‌شود. فایل تازه‌ای که قبلاً نبوده حذف و فایل قدیمی موجود بازگردانده می‌شود. اگر نسخهٔ قبل فایل عمومی قدیمی داشته، بازگشت همان وضعیت را برمی‌گرداند؛ نقص امنیتی نسخهٔ قدیم نیز برمی‌گردد، پس rollback راهکار موقت عملیاتی است.

موفقیت: `CODE ROLLBACK COMPLETE.` — **DB فعلی، حساب‌ها، اطلاعات و تغییرات بعد از نصب بازنویسی نمی‌شوند.** snapshot database.sqlite3 برای حفاظت جداگانه است، نه restore خودکار. restore دیتابیس فقط در رخداد جداگانه، با توقف همهٔ workerها، بررسی backup و تصمیم صریح مدیر انجام شود؛ می‌تواند تغییرات بعدی را از بین ببرد. فایل SQLite را روی WAL زنده کپی نکنید.

## ۶. وضعیت آزمون و محدودیت‌ها

- آزمون‌های Python شامل API، permission/scope، backup/restore، parser/timeout، bootstrap، ticket replay، رقابت درخواست‌ها، هماهنگی میان فرایندهای مستقل، masking و قرارداد mock ویندوز است؛ SSH واقعی جایگزین آزمایشی داشته است.
- آزمون مرورگر واقعی با executor ساختگی، مسیر inspect و status-only، مالکیت پورت، تأیید/انصراف، IP دستی، متن امن، توقف دسته در uncertainty/still-error و RAM-only را بررسی می‌کند.
- همسانی source/payload/HTML و hash ZIP بررسی می‌شود. syntax پاورشل با parser بررسی شده، **نه اجرای Windows PowerShell**.
- اجرای واقعی Windows/IIS، Job Object کرنل ویندوز، ASKPASS با نسخهٔ سازمان، RADIUS و تجهیزات واقعی در این محیط انجام نشده‌اند؛ پذیرش محیط تست قبل از تولید لازم است. هیچ credential واقعی یا DB تولیدی استفاده نشده است.
- بازطراحی KDF/versioning، rate-limit بر اساس IP پشت ARR و CSP کامل جزو این اصلاحات نیستند. محدودیت lockout سراسری بر مبنای نام کاربری و ملاحظات proxy همچنان طبق SECURITY_NOTES.md باقی‌اند. این‌ها را با نقص‌های رفع‌شده یکی نگیرید و از این پچ ادعای «امنیت مطلق» نکنید.

اعداد نهایی اجرای تست و checksum در گزارش تحویل و فایل `.sha256` همراه بسته آمده‌اند؛ checksum را داخل خود ZIP درج نمی‌کنیم تا وابستگی دوری ایجاد نشود.


## به‌روزرسانی ظاهریِ همان نسخه — ۲۰۲۶-۱۰-۱۸

لوگوی اصلی منو و نام کامل «تجارت الکترونیک و فناوری اطلاعات ملل (فام)» به صفحهٔ ورود و بالای انتخاب دو فضای کاری اضافه شده است. تجهیزات دیگر افکت مشترک داشبورد را مخفی نمی‌کند و پس‌زمینهٔ تخت جدا ندارد؛ تنظیم تم ذخیره‌شده و کاهش حرکت حفظ می‌شود. نشان ظاهری `fam-brand-release` برابر `FAM-BRAND-BACKGROUND-20261018` است. این بخش منطق اتصال، رفع پورت، حساب‌ها یا داده را تغییر نمی‌دهد. تصویر اصلی در فایل HTML تعبیه شده و فایل جانبی تازه‌ای برای نصب لازم نیست.


## تشخیص فقط‌خواندنی کلاینت شعب — اضافه‌شده در این بسته

در تجهیزات ← بررسی پورت‌ها، بخش «تشخیص فقط‌خواندنی جابه‌جایی کلاینت» اضافه شده است. سوئیچ‌های مجاز و IP یا MAC کلاینت را وارد کنید؛ شمارهٔ پورت لازم نیست. پروفایل اولیه WS-C2960-24TT-L / VLAN 100 است و مدل/IOS در مرحلهٔ اول خوانده می‌شود. اگر قابل تأیید نباشد ادامه نمی‌دهد. شواهد MAC پویا، MAC مجاز، source binding و لاگ تاریخی DAI با اطمینان متوسط/کم یا نتیجهٔ نامشخص نمایش داده می‌شوند؛ هیچ جابه‌جایی قطعی یا سلامت تضمینی اعلام نمی‌شود. Sticky/ACL/binding/IPSG و وضعیت پورت تغییر نمی‌کنند. هیچ ticket رفع از این مسیر صادر نمی‌شود.

فایل جدید `equipment_diagnostics.py` ضروری است؛ payload اکنون ۲۲ فایل دارد. راهنمای کامل و محدودیت‌ها داخل ZIP با نام `CLIENT-MOVE-DIAGNOSIS-FA.txt` قرار دارد. برای rollback از backup همین نسخه و همین updater استفاده کنید؛ manifest نسخه‌های متفاوت ممکن است سازگار نباشد. اجرا روی IOS واقعی شعبه همچنان نیازمند پذیرش محیط تست است.


## تعویض MAC با پورت اعلام‌شده — IP بدون تغییر

کنار هر سوئیچ، پورت اختیاری و تیک IP دستی اضافه شده است. پورت خالی همان مسیر رفع Err-disabled قبلی است. پورت واردشده، پیش‌بررسی و تأیید جداگانهٔ تعویض MAC دارد. با تیک دستی، IP و MAC قدیمی از binding همان پورت خوانده شده و فقط MAC در binding و `Inspection` جایگزین می‌شود؛ IP از شمارهٔ پورت ساخته نمی‌شود. فایل جدید `equipment_replacement.py` در allowlist نصب و rollback لحاظ شده است.

**محدودیت مهم:** Sticky/Configured قبلی خودکار پاک نمی‌شود؛ آن حالت قبل از تغییر متوقف می‌شود. خطای یادگیری ممکن است پورت را در shutdown بگذارد؛ قطع SSH می‌تواند حفاظت را نامشخص کند و بررسی فوری لازم است. هیچ ذخیرهٔ تنظیمات یا تست واقعی سوئیچ انجام نشده است. راهنمای کامل توالی، بودجهٔ زمانی، شکست/قرنطینه و پذیرش: `CLIENT-MAC-REPLACEMENT-FA.txt` داخل ZIP، معادل `docs/CLIENT_MAC_REPLACEMENT_FA.md`.
