# اتصال، بررسی Err-disabled و رفع با Ansible — مستقل از FAM

این بسته بازنویسی **عملیات اتصال/بررسی/رفع پورت** با Playbookهای واقعی Ansible است؛ wrapper اجرای ssh.exe یا کد قبلی نیست. Playbookها YAML هستند و filter، callback و آداپتور محدودکنندهٔ IOS به زبان Python (سازوکار استاندارد افزونه‌های Ansible) نوشته شده‌اند.

**این کد هنوز جایگزین سرویس فعال FAM نشده است.** نشست، مجوزهای پنج‌گانه، Origin/CSRF و ticket مرورگر FAM در اجرای مستقل Ansible وجود ندارند. کنترلر و حساب سیستم‌عامل آن باید فقط در اختیار اپراتور مجاز باشند. اتصال به API FAM و انتقال دسترسی‌ها نیاز به پروژهٔ ادغام جداگانه دارد. هیچ SSH واقعی هنگام ساخت/آزمایش این بسته اجرا نشده است.

## راه‌اندازی روی کنترلر Linux یا WSL

Ansible controller به‌صورت native روی Windows/IIS اجرا نمی‌شود. Python 3.11+ و Git لازم است. Linux/WSL باید به شبکهٔ تجهیزات دسترسی داشته باشد. کتابخانهٔ libssh باید cipherهای تنظیم‌شده را پشتیبانی کند؛ سازگاری تجهیزات قدیمی فقط با تست مجاز محلی مشخص می‌شود.

از پوشهٔ همین بسته و در محیط مجازی جدا:

```sh
umask 077
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
ansible-galaxy collection install -r requirements.yml --no-deps
export ANSIBLE_CONFIG="$PWD/ansible.cfg"
ansible-playbook inspect.yml --syntax-check
ansible-playbook recover.yml --syntax-check
```

نسخه‌های ansible-core، ansible-pylibssh و هر سه collection pin شده‌اند. در محیط آفلاین وابستگی‌ها را قبلاً با روش مصوب خودتان آماده کنید؛ wheel/collection داخل این ZIP نیست. `inventory.ini` فقط کنترلر و یک گروه خالی دارد؛ مقصد، نام کاربری و رمز در فایل موجودی نوشته نمی‌شوند.

قبل از اتصال، کلید عمومی هر تجهیز را **با اثرانگشت تأییدشده از مسیر مستقل** در `~/.ssh/known_hosts` کنترلر قرار دهید. خروجی ssh-keyscan به‌تنهایی اثبات اعتماد نیست. کلید ناشناخته یا تغییرکرده رد می‌شود؛ auto-add خاموش است.

## فقط بررسی — بدون تغییر

```sh
ansible-playbook inspect.yml
```

در promptها یک تا پنج IPv4 را با کاما، سپس حساب SSH/RADIUS و رمز را وارد کنید. ورودی‌های حساس مخفی‌اند. رنج‌های مجاز RFC1918 و `100.64.0.0/10` هستند؛ `100.100.1.22`، `100.108.1.22` و `100.107.1.22` پذیرفته می‌شوند. همهٔ 100/8 یا IPهای عمومی باز نشده‌اند.

بررسی فقط `show interfaces status` را می‌خواند. جدول کامل باید معتبر باشد؛ pagination، دادهٔ ناقص، سطر تکراری و خطای اتصال هرگز «بدون خطا» نیستند. فقط شناسهٔ پورت‌های err-disabled/errdisable/errdisabled گزارش می‌شود؛ disabled/notconnect/connected خطا محسوب نمی‌شوند. بنر، Name، متن CLI و اطلاعات اتصال گزارش نمی‌شوند. مسیر نمایش show int des در برنامهٔ اصلی در این Playbook مستقل منتقل نشده است.

## رفع — تأیید دقیق، بررسی قبل و بعد

```sh
ansible-playbook recover.yml
```

هدف‌ها را به صورت `IP:interface` وارد کنید؛ مثلاً `100.100.1.22:Gi0/7,100.108.1.22:Gi0/8`، حداکثر پنج جفت، بدون تکرار. پس از دیدن فهرست معتبر، برای تأیید باید **عین طرح** را با پیشوند `REPAIR ` تایپ کنید؛ برای نمونه:

```text
REPAIR 100.100.1.22:Gi0/7,100.108.1.22:Gi0/8
```

Enter خالی یا متن متفاوت قبل از هر اتصال لغو می‌کند. فرمان‌ها را با `--extra-vars` یا فایل هدف/رمز به کار نبرید. پارامتر فرمان آزاد وجود ندارد. هر سوئیچ و هر پورت یکی‌یکی بررسی می‌شود:

1. جدول وضعیت کامل دوباره خوانده می‌شود؛ همان پورت باید وجود داشته باشد.
2. اگر دیگر err-disabled نیست: `not_errdisabled`، بدون تغییر.
3. فقط روی همان interface: `configure terminal` → `interface ...` → `shutdown` → `no shutdown` → `end`.
4. جدول وضعیت دوباره خوانده و حضور همان پورت بررسی می‌شود. نتیجه فقط `recovered`، `still_errdisabled` یا نامشخص است.

نتیجهٔ `recovered` فقط یعنی همان پورت در بررسی بعدی دیگر err-disabled نیست، نه تأیید connected بودن یا سلامت کامل شبکه. این cycle علت ریشه‌ای مانند BPDU Guard، Port Security یا UDLD را تغییر/غیرفعال نمی‌کند و خطا ممکن است برگردد.

هر شکست یا نتیجهٔ حل‌نشده، نوشتن‌های بعدی دسته را متوقف می‌کند. `--check` و `--diff` پیش از اتصال رد می‌شوند. `match: none` برای اجرای هر دو فرمان مرتب ضروری است؛ idempotence معمول ios_config ممکن است cycle را حذف کند. `running_config: "!"` همراه آداپتور محدودکننده، مانع جمع‌آوری running-config کامل می‌شود.

## مرزهای ایمنی و تفاوت حمل‌ونقل

- `become` و Enable خاموش؛ حساب باید از قبل مجوز لازم و prompt مناسب داشته باشد. مجوز ناکافی خطاست؛ روش ورود یا ارتقای دسترسی خودکار عوض نمی‌شود.
- ذخیرهٔ کانفیگ، backup، write memory، copy running-config، فرمان آزاد و جمع‌آوری facts ممنوع‌اند.
- افزونهٔ `fam_ios` جلوی discovery پیش‌فرض show version/show vlan و خواندن full config را می‌گیرد. آماده‌سازی نشست فقط `terminal length 0` است.
- transport برابر `network_cli + libssh` است، نه Windows OpenSSH. در `ssh_config` cipherهای مدرن و فقط استثنای `aes128-cbc` مجازند؛ 3des-cbc/aes192-cbc/aes256-cbc نیستند. گزینهٔ OpenSSH `-o Ciphers=...` را برای libssh جایگزین این فایل نکنید.
- اتصال ۱۰ و فرمان ۲۵ ثانیه، یک تلاش اتصال، بدون retry خودکار تعریف شده است. این‌ها timeoutهای Ansible هستند، نه همان deadline کلی helper ویندوز. پس از timeout/قطع ارتباط، نتیجه را نامشخص بدانید و پیش از هر تکرار دستی دوباره بررسی کنید؛ توقف کنترلر تضمین لغو فرمان قبلاً ارسال‌شده نیست.
- credential، طرح عملیاتی و نتایج در حافظه‌اند؛ fact cache برابر memory، log اتصال خاموش، taskهای حساس no_log و اتصال persistent در پایان/خطا reset می‌شود. سوکت موقت IPC خود Ansible حاوی فایل رمز نیست؛ کنترلر اختصاصی و پوشهٔ home خصوصی لازم است.
- callback اختصاصی فقط طرح معتبر و نتیجهٔ پالایش‌شده را چاپ می‌کند، نه خطاهای خام. با callback یا logger سفارشی، fact cache دیسکی، `ANSIBLE_LOG_PATH`، debug/verbosity یا ضبط ترمینال اجرا نکنید. رمز را در argv، inventory، فایل متغیر، playbook یا chat نگذارید.
- تنظیمات پروژه و افزونه‌ها را دست‌نخورده نگه دارید. اپراتوری که کد/تنظیمات/extra-vars را تغییر دهد خارج از این قرارداد است؛ این بسته یک sandbox یا جایگزین احراز هویت وب نیست.

## اعتبارسنجی

Syntax هر دو playbook با نسخه‌های pin‌شده بررسی شد. **۱۷ تست** موفق: parser/IPv4/مرزها/تزریق/خطای خروجی، ترتیب دقیق فرمان‌های آداپتور و اجرای خود موتور Ansible با actionهای کاملاً ساختگی. انصراف بدون عملیات، pre-check پاک بدون نوشتن، جدول ناقص، شکست اتصال، post-check گم‌شده و باقی‌ماندن خطا پوشش دارند. در آزمون موتور Ansible، actionهای transport جایگزین شده‌اند؛ اتصال واقعی، رمز واقعی، RADIUS، cipher negotiation و سخت‌افزار آزمایش نشده‌اند. ابتدا در آزمایشگاه و با مجوز تست کنید.
