# پیش‌نمایش LOCAL انتخاب سوئیچ و مسیر تعویض MAC — بازنگری دوم

فایل: `releases/FAM-Client-MAC-LOCAL-Preview.zip`، شامل HTML مستقل و `README_FA.txt`.

## بازکردن

ZIP را استخراج و HTML را با Chrome/Edge باز کنید. برای حساب تازهٔ محلی: `admin` / `1109`؛ این حساب برنامه است، نه رمز تجهیز. حساب‌ها/اطلاعات موجود ریست نمی‌شوند. مسیر: ورود ← تجهیزات ← بررسی پورت‌ها.

## انتخاب بدون تاریخچه و لیست دائمی

- یک کادر **IP یا نام سوئیچ** وجود دارد؛ فهرست دائمی همهٔ سوئیچ‌ها یا کادر جداگانهٔ IP دستی حذف شده است.
- کلیک روی کادر، نوار انتخاب را زیر آن باز می‌کند: **منطقه ← ساختمان/شعبه (نوع محل) ← محل ← سوئیچ‌ها**. نام‌ها از catalog موجودی مجاز خوانده می‌شوند، نه فهرست ثابت. با breadcrumb می‌توانید به سطح قبل برگردید.
- کنار سوئیچ‌های موردنظر تیک بزنید. فقط انتخاب‌شده‌ها زیر کادر می‌مانند. نام/IP را هم می‌توانید جست‌وجو کنید؛ نام‌های تکراری بدون تیک صریح انتخاب نمی‌شوند.
- IP داخلی کامل را در همان کادر بنویسید و Enter بزنید. IP ثبت‌شده به همان تجهیز نگاشت می‌شود؛ IP ناشناخته فقط هدف موقت برای مرور فرم است، نه رکورد جدید موجودی. انتخاب تکراری ایجاد نمی‌شود و تنظیمات پورت قبلی حفظ می‌شوند.
- تا پنج سوئیچ در هر نوبت؛ حذف/برداشتن تیک هدف دستی آن را از هدف‌های موقت پاک می‌کند. سوئیچ‌های موجودی حذف نمی‌شوند. هیچ history یا انتخابی در storage ذخیره نمی‌شود. refresh هدف‌ها/انتخاب‌های موقت را پاک می‌کند.
- Esc، دکمهٔ بستن و کلیک بیرون نوار آن را می‌بندند. انتخاب با Tab و Space/Enter نیز امکان‌پذیر است.

## پورت و طرح رفع گروهی

کنار هر سوئیچ، پورت اختیاری و تیک IP دستی وجود دارد. چند پورت را با ویرگول وارد کنید: `6,10` یا `۶،۱۰`. اعداد ۱ تا ۲۴ مجازند؛ تکراری‌ها حذف و اعضا مرتب می‌شوند. ورودی مثل `6-10` یا فرمان CLI پذیرفته نمی‌شود تا پورت اضافی ناخواسته انتخاب نشود.

- **خالی:** طرح موردنظر برای SERVER این است که خطاها خوانده شوند، کارشناس فقط پورت‌های خطادار موردنظر را تأیید کند و اعضای همان سوئیچ به‌صورت گروهی کار شوند. LOCAL هیچ خطا یا شمارهٔ پورتی را حدس نمی‌زند.
- **پورت پر:** مسیر همان اعضا نمایش داده می‌شود؛ مثلاً برای ۶ و ۱۰:

```text
interface range FastEthernet0/6 , FastEthernet0/10
```

پورت‌های ۷، ۸ و ۹ عضو نیستند. پورت‌های سوئیچ‌های مختلف در یک range قرار نمی‌گیرند. برای یک پورت از `interface` استفاده می‌شود.

نمایشگر می‌تواند فقط اعضای متوالیِ صریح را فشرده کند؛ مثلاً `1,2,3,6` به `FastEthernet0/1 - 3 , FastEthernet0/6` تبدیل می‌شود، نه انتخاب پورت‌های ۴ و ۵. هر فرمان حداکثر پنج clause دارد و گروه بزرگ‌تر به چند فرمان گروهی تقسیم می‌شود. فاصلهٔ دو طرف ویرگول و محدودیت پنج range مطابق راهنمای کلاسیک 2960 است. [1](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst2960/software/release/12-2_53_se/configuration/guide/2960scg/swint.html)

- **تیک دستی:** IP هر پورت باید از binding همان پورت خوانده شود و بدون تغییر بماند؛ MAC آن جایگزین می‌شود. binding و permit ARP ACL هر IP مستقل‌اند و فرمان interface range جایگزین مدیریت مستقل آن‌ها نیست.
- **بدون تیک:** binding ثابت و ARP ACL بازنویسی نمی‌شوند.

## طرح برخورد با MAC روی پورت قبلی

در طرح نمایش‌داده‌شده، پیش از رفع نهایی باید برای هر پورت، شواهد MAC متعارض بررسی و همان MAC در secure-addressهای **همان سوئیچ** جست‌وجو شود. اگر پورت قبلی و جابه‌جایی تأیید شد، MAC و پورت قبلی/جدید در تأیید عملیات نمایش داده شده و فقط همان رکورد، متناسب با Sticky/Configured/Dynamic بودن، از محل قبلی حذف می‌شود. بعد پورت‌های جدید از خطا خارج می‌شوند. پاک‌کردن همهٔ Stickyها یا همهٔ MACهای پورت مجاز نیست.

صرف رکورد قدیمی/Last Source Address تاریخی، MAC روی uplink یا IP مشابه مجوز حذف نیست. در شواهد مبهم یا چند دستگاه، طرح باید متوقف شود. این صفحه MAC جدید/پورت قبلی را شبیه‌سازی نمی‌کند، چون هیچ خروجی واقعی سوئیچ در LOCAL وجود ندارد.

**وضعیت اجرا:** پاک‌سازی MAC از پورت قبلی و رفع با interface range در این نسخه فقط **پیش‌نمایش طرح درخواستی** هستند. کد اجرایی SERVER هنوز همان نسخهٔ قبلی است: رفع پورت منفرد و توقف در Sticky/Configured قبلی. این دو قابلیت اجرایی و انتخاب‌گر جدید به SERVER منتقل نشده‌اند و نباید این فایل را پچ اجرایی آن‌ها تلقی کرد.

## بخش ۳ برای چیست؟

«تشخیص فقط‌خواندنی جابه‌جایی کلاینت» مخصوص وقتی است که **پورت را نمی‌دانید**. در SERVER، با IP یا MAC کلاینت شواهد MAC table، source binding و لاگ DAI خوانده می‌شوند تا پورت احتمالی پیدا شود. هیچ تغییر MAC/binding/ACL یا رفع خطایی انجام نمی‌دهد؛ نتیجه ممکن است تاریخی یا ناقص باشد و تشخیص قطعی تضمین نمی‌شود. وقتی کارشناس پورت را اعلام می‌کند، نیازی به آن ندارید. در LOCAL فقط توضیح جمع‌شونده وجود دارد؛ حتی خواندن سوئیچ هم اجرا نمی‌شود.

## مرز ایمنی و پذیرش

**هیچ SSH، گرفتن MAC، نتیجهٔ ساختگی سالم/موفق، تغییر سوئیچ یا دریافت رمز تجهیز نداریم.** نمونهٔ فرمان فقط نمایش است، نه سناریوی کامل مستقل برای اجرا. در اجرای واقعی، توقف/خطای یادگیری ممکن است پورت را بسته بگذارد و قطع SSH ممکن است حفاظت را نامشخص کند؛ این حالات نیازمند بررسی کارشناس هستند.

ساخت بازتولیدپذیر: `python scripts/build_mac_local_preview.py`. فقط variant جدید ساخته می‌شود؛ `FAM.html` اصلی و SERVER/payload/ZIP قبلی تغییر نمی‌کنند. marker: `FAM-LOCAL-MAC-PREVIEW-20261018`. CSS و JavaScript پیش‌نمایش فقط در همین variant تزریق می‌شوند.

پذیرش: `node --test tests/equipment-mac-local-preview.test.cjs`، **۹ تست پاس**: درخت پویا، انتخاب چندگانه، جست‌وجوی نام/IP، ابهام نام، حذف بدون history، سقف انتخاب، IP خصوصی، تکراری‌ها، پورت‌های فارسی/لاتین، فقط اعضای ۶ و ۱۰، batch پنج clause و فشرده‌سازی بدون افزودن عضو، تفکیک سوئیچ‌ها، تغییر/باطل‌شدن پیش‌نمایش، توضیح بخش ۳، متن امن، کلیک بیرون، ورود واقعی به HTML با file://، نبود credential و HTTP(S)، عدم ثبت هدف در موجودی، refresh و عرض‌های ۳۹۰/۷۶۸/۱۴۴۰ در دو theme. هیچ خطای JavaScript یا درخواست HTTP(S) مشاهده نشد. تجهیزات واقعی و Windows/IIS دخیل نیستند.
