**قاعده‌های ایستادهٔ همین سند:**

1. تصویر IOS/IOL و لایسنس سیسکو را **تولید یا توزیع نمی‌کنیم** — فقط از منابع قانونی شرکت/CML شما استفاده می‌شود.

5. کلید میزبان SSH سخت‌گیرانه است: **هرگز** `StrictHostKeyChecking=no` نمی‌گذاریم؛ کلید را اول با کنسول تجهیز تطبیق می‌دهیم.
6. FAM هرگز `enable` / `write memory` / فرمان آزاد نمی‌فرستد؛ پیکربندی اولیهٔ سوئیچ فقط «راه‌اندازی اولیه» با دستِ شما از کنسول است.

## ۲. گام A — تهیه و تأیید ISO (در ویندوز / PowerShell)

1. نسخهٔ **Freemium 7.2.0-18** را از سایت eve-ng.net بخش Freemium دریافت کنید — گزینهٔ «EVE-NG PRO installation Full ISO» (همان ISO رایگان؛ سقف ۷ نود). می‌توانید از مرورگر یا سیستم شرکت دانلود کنید؛ اگر با curl دانلود می‌کنید حتماً `--ssl-no-revoke` بگذارید.
2. هش فایل را با این دستورِ تکی بررسی کنید (مسیر فایل را جایگزین کنید):

```powershell

```

3. یا اسکریپت کمکی پروژه را بگیرید و اجرا کنید. **ابتدا آدرس را چشمی چک کنید** (پیستِ لینک از گفت‌وگو ممکن است آدرس را خراب کند):

```powershell
curl.exe --ssl-no-revoke -L -o "$env:USERPROFILE\Downloads\verify_eve_iso.ps1" https://raw.githubusercontent.com/mohsenmehri/divergenc/arena/06b5f68a-divergenc/lab/eve/verify_eve_iso.ps1
```

اگر فایل ISO داخل پوشهٔ Downloads است، می‌توانید بدون `-Path` اجرا کنید (خودش فایل را پیدا می‌کند):

```powershell
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\verify_eve_iso.ps1"
```

اگر فایل ISO جای دیگری است یا چند فایل ISO در Downloads دارید، مسیر دقیق را بدهید (نام واقعی فایل را با Tab یا `dir *.iso` پیدا کنید):

```powershell
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\verify_eve_iso.ps1" -Path "C:\Users\Mohsen\Downloads\نام-واقعی-فایل.iso"
```

- خروجی مورد انتظار (اسکریپت عمداً انگلیسی/ASCII است تا در Windows PowerShell بدون مشکل نویسه‌ای اجرا شود):

## ۴. گام C — نصب EVE-NG (ترمینال VM)

> **مشاهدهٔ عملی (۲۰۲۶/۱۰/۲۰):** ISO نسخهٔ 7.2.0-18 بدون نصابِ متنیِ تعاملی بالا آمد و مستقیم به پرامپت ورود `localhost login:` رسید. پیام‌های boot طبیعی بودند: «Eve-NG (default root password is 'eve')» (ورود: `root` با رمز `eve`)، «WARNING: neither Intel VT-x or AMD-V found» (Nested VT در دسترس نیست و برای نود IOL لازم نیست) و «No IP address on interface eth0» (VMnet1 معمولاً DHCP ندارد؛ با IP ثابت حل می‌شود). سیستم‌عامل پایه Ubuntu 24.04 با cloud-init است. پس از ورود، ابزار «Eve-NG Setup 7.2.0-18» (فرم آبی) باز می‌شود: Hostname / Domain / Use DHCP / NTP / Root Password — «Use DHCP» باید برداشته شود و IP ثابت `192.168.97.130` داده شود؛ تأیید نهایی با `ip a` و `lsblk`. **مشاهدهٔ بعد از Apply (۲۰۲۶/۱۰/۲۰):** فرم بسته شد ولی `eth0`/`eth1` پایین (`DOWN`، بدون IP) ماندند و `ping` به 192.168.97.128 «Network is unreachable» داد — یعنی Apply تنظیمات را می‌نویسد ولی interfaceها را بلافاصله بالا نمی‌آورد؛ قدم بعد: `reboot` و بررسی دوباره. **مشاهدهٔ بعد از reboot (۲۰۲۶/۱۰/۲۰):** فرم Setup دیگر برنگشت و هیچ‌چیز ذخیره نشده بود (hostname هنوز `localhost`، eth0/eth1 همچنان بدون IP؛ ورود root ممکن است) — یعنی Apply فرم چیزی ذخیره نکرده (احتمالاً به‌خاطر فیلدهای اجباری Gateway/DNS با علامت `!`). راه‌حل: پیکربندی دستی شبکه پس از بازرسی `cat /etc/network/interfaces` و `ls /etc/netplan` و `lsblk`. رابط‌های داخلی EVE (`nat0` با 172.29.129.254، `wg0`، `eve-n0`، `docker0`) طبیعی‌اند. **بازرسی‌ها (۲۰۲۶/۱۰/۲۰):** `lsblk` → سیستم روی `sda` (LVM، ۸۰ گیگ، ریشه روی `/`) نصب است و ماندگاری تضمین است؛ `ls /etc/netplan` خالی است؛ `/etc/network/interfaces` فقط `natmac`/`nat0` (شبکه‌های داخلی EVE) را دارد و بخش مدیریت (`pnet0`) نوشته نشده — همین علت نبودِ IP است. راه‌حل انتخابی: ساخت `/etc/network/interfaces.d/pnet0.cfg` (پل استاندارد `pnet0` روی `eth0` با IP ثابت `192.168.97.130/24`) و `ifup pnet0`؛ اگر بعداً اتصال نود به Management(Cloud0) جواب نداد، پیکربندی به `eve-n0` منتقل می‌شود. **نتیجه (۲۰۲۶/۱۰/۲۰):** pnet0 با موفقیت بالا آمد (eth0 با `master pnet0` و IP `192.168.97.130/24` روی pnet0) ولی ping به 192.168.97.128 از نوع «Destination Host Unreachable» بود — یعنی پاسخ ARP نمی‌آید؛ محتمل‌ترین علت: خاموش/خارج از VMnet1 بودن FAM-Ubuntu. بررسی سه‌طرفه: ping از ویندوز به `.128` و `.130`.

1. VM را روشن کنید (Power on). نصاب متنی EVE-NG بالا می‌آید؛ با Enter روی **Install** (یا همان گزینهٔ نصب) بروید جلو.

## ۶. گام E — انتقال فایل‌های IOL به EVE

> یادآوری: تصویر IOL و لایسنس را فقط از منبع قانونی شرکت/CML شما می‌گیریم. نام فایل‌ها را در مثال‌ها با فایلِ خودتان جایگزین کنید.

1. اگر لایسنسِ IOL (معمولاً `iourc.txt`) از منبع قانونی دارید، همراه تصویر آماده باشد. اگر تصاویر شما از نوع جدید CML هستند و لایسنس جدا ندارند، همان تصاویر کافی‌اند.
2. در **PowerShell ویندوز**، فایل‌ها را به EVE بفرستید (مسیر فایل‌های خودتان را بنویسید):

```powershell
scp "C:\Users\Mohsen\Downloads\L2-ADVENTERPRISEK9-M-15.2-1.bin" root@192.168.97.130:/opt/unetlab/addons/iol/bin/
```

```powershell
scp "C:\Users\Mohsen\Downloads\iourc.txt" root@192.168.97.130:/opt/unetlab/addons/iol/bin/
```

- اگر SSH با root قبول نشد، با کاربر ساخته‌شده در نصب بفرستید و بعد در ترمینال EVE دستور اجازه را با `sudo` بزنید.
3. در **ترمینال EVE** (SSH یا کنسول VM) این دستورِ تکی را بزنید (بعد از هر بار اضافه‌کردن تصویر لازم است):

```bash
/opt/unetlab/wrappers/unl_wrapper -a fixpermissions
```

4. بررسی سریع:

```bash
ls -l /opt/unetlab/addons/iol/bin/
```

- خروجی مورد انتظار: نام فایل‌های منتقل‌شده.

> ✅ اسکرین‌شات `ls -l` را بفرستید (نام فایل‌ها مهم است؛ محتوای تصویر را هرگز نمی‌فرستیم).

## ۷. گام F — ساخت نود سوئیچ IOL و IP آزمایشی

1. در وب‌UI EVE: یک لابراتوی جدید بسازید (مثلاً نام `fam-lab`) و بازش کنید.
2. روی صفحهٔ خالی راست‌کلیک → **Node** → نوع: **IOL** (Cisco IOL) با این تنظیمات:

- **Image**: فایلی که بالا فرستادید (از فهرست انتخاب کنید).
- **Name**: `sw1`
- **Number of nodes**: `1`
- **RAM**: `1024` MB
- **Ethernet adapters**: `8`
- **Serial adapters**: `0`
- بقیه: پیش‌فرض → **Save**.

3. نود ظاهر می‌شود. حالا کابل بکشید: از نود `sw1` (پورت **e0/0**) به گوشهٔ بالای صفحه، شیء **Management (Cloud0)**. (درگیر کردن پورت‌ها: e0/0 → Management.)
4. روی نود راست‌کلیک → **Start**. چند لحظه صبر کنید تا IOS بالا بیاید.

## ۹. گام H — تأیید کلید میزبان SSH (در FAM-Ubuntu)

1. با SSH وارد FAM-Ubuntu شوید (از PowerShell ویندوز: `ssh mohsen@192.168.97.128`).
2. اسکریپت کمکی را در همان اتصالِ اوبونتو دانلود کنید (آدرس را چشمی چک کنید؛ این دستورِ **اوبونتو** است، نه ویندوز):

```bash
curl -L -o ~/scan_iol_hostkey.sh https://raw.githubusercontent.com/mohsenmehri/divergenc/arena/06b5f68a-divergenc/lab/eve/scan_iol_hostkey.sh
```

3. اسکن یک‌باره و نمایش کلید:

```bash
sh ~/scan_iol_hostkey.sh 192.168.97.140
```

4. **تطبیق دستی (اجباری):** در کنسول سوئیچ (گام F) این دستور را بزنید:

```text
show crypto key mypubkey rsa
```

- متن Base64 کلید را با خروجی اسکریپت (سطر `ssh-rsa AAAA...`) مقایسه کنید — ابتدا و انتهای رشته کافی است. اسکرین‌شات هر دو را بفرستید.
5. **فقط اگر یکسان بودند**، کلید را به فایل کلیدِ FAM اضافه کنید:

```bash
cat ~/iol-hostkey.txt >> ~/FAM-Linux-Lab/data/equipment_known_hosts
```

6. (اختیاری) آزمایش SSH دستی با همان سخت‌گیری — نه هیچ گزینهٔ دورزدنی:

```bash
ssh famadmin@192.168.97.140
```

- اگر پرسید `Are you sure you want to continue connecting (yes/no)?` — یعنی کلید هنوز در `~/.ssh/known_hosts` کاربر نیست؛ اثرانگشت نمایش‌داده‌شده را با کلیدِ کنسول مقایسه کنید و اگر یکسان بود `yes` را تایپ کنید (این جریانِ طبیعی و سخت‌گیرانه است).
- پس از ورود: `show interfaces description` را بزنید و با `exit` خارج شوید.

> ✅ اسکرین‌شات مقایسهٔ کلیدها و نتیجهٔ مرحلهٔ ۵ را بفرستید.

## ۱۱. گام I — اولین بررسی فقط‌خواندنی

1. در همان مرکز تجهیزات → تب **بررسی تجهیزات**.

## ۱۲. عیب‌یابی سریع

| نشانه | بررسی |
|---|---|
| مرورگر به `192.168.97.130` نمی‌رسد | در ترمینال EVE: `ip a` و `ping -c 2 192.168.97.1`؛ کارت اول باید VMnet1 باشد |
| نود IOL استارت نمی‌شود | دوباره `fixpermissions` را بزنید؛ نام تصویر را در پوشهٔ `iol/bin` بررسی کنید؛ اسکرین‌شات پیام خطا |
| SVI بالا نمی‌آید (up/down) | کابل e0/0 به Management(Cloud0) وصل باشد؛ `no shutdown` روی vlan 1 زده شده باشد |
| `ssh-keyscan` کلیدی نگرفت | سوئیچ بالا باشد؛ `show ip interface brief`؛ SSH با `show ip ssh` (اگر بود) |
| خطای `no matching host key type found` یا `no matching cipher found` | اسکرین‌شات بفرستید — این مورد به تصمیم مالک برای یک استثنای **هدفمند** (و نه wildcard) در کد نیاز دارد؛ بدون تصمیم، کد را تغییر نمی‌دهیم |
| FAM می‌گوید نام کاربری/رمز نامعتبر | نام کاربری فقط ASCII ساده؛ رمز فقط نویسه‌های ASCII معمولی |
| FAM کلید میزبان را نمی‌پذیرد | `cat ~/FAM-Linux-Lab/data/equipment_known_hosts` را بررسی کنید؛ کلید باید از همان اسکنِ تأییدشده اضافه شده باشد |
| وب‌UI یا ping بین ویندوز و VMها جواب نمی‌دهد | در `ipconfig` ویندوز، آدرس کارت VMnet1 باید `192.168.97.1` باشد؛ اگر زیرشبکهٔ دیگری (مثلاً `192.168.198.x` — پیش‌فرض VMware) دیدید: Edit → Virtual Network Editor → VMnet1 → Subnet `192.168.97.0` / `255.255.255.0` (درس ۲۰۲۶/۱۰/۲۰) |
| FAM-Ubuntu آدرس قدیمی دارد (مثلاً `192.168.198.x`) | این ماشین DHCP است؛ یک بار `sudo reboot` کنید تا دوباره اولین آدرس استخر (`192.168.97.128`) را بگیرد؛ `ip a` را تأیید کنید |
| ping به EVE (`192.168.97.130`) بی‌جواب می‌ماند ولی سایت باز می‌شود | طبیعی است — فایروال EVE به ICMP پاسخ نمی‌دهد؛ ملاک، بازشدن `https://192.168.97.130` است |

## ۱۳. یادآوری کوتاه قواعد

- تصویر/لایسنس IOS: تولید/توزیع/ضبط نمی‌کنیم؛ فقط منبع قانونی شرکت.
