# دو تم در فایل اصلی FAM.html

بنا به درخواست کاربر، ظاهر دوم دیگر صرفاً یک برنامهٔ جدا نیست؛ **هر دو تم در همان `FAM.html`** قرار دارند.

- **تم ۱ — اصلی:** ظاهر قبلی با همان پس‌زمینه‌ها و چیدمان اصلی؛ پیش‌فرض برای مرورگری که هنوز تم انتخاب نکرده است.
- **تم ۲ — روشن:** ظاهر روشن میزکار عملیاتی، بدون اجرای پس‌زمینهٔ متحرک، با عملیات بالاتر از دسته‌بندی‌ها.
- دکمهٔ «تم ۱ / تم ۲» در نوار بالای برنامه، صفحهٔ ورود و نمای محدود سطح ۴ قرار دارد.
- انتخاب تم با کلید مستقل `fam.ui.theme` در همان مرورگر ذخیره می‌شود؛ بارگذاری مجدد لازم نیست.
- پیش‌نویس‌ها، فرم‌های باز، داده‌ها، حساب‌ها، نقش‌ها و وضعیت باز/بسته‌بودن منو هنگام تغییر تم حفظ می‌شوند. هیچ ورود فایل یا بازسازی workbook برای تغییر تم انجام نمی‌شود.
- تم روشن قبل از نمایش بدنه اعمال می‌شود؛ در صورت خرابی/نبودن مقدار ذخیره‌شده، فایل اصلی با تم اصلی شروع می‌شود. اگر ذخیرهٔ ترجیح تم ممکن نباشد، تغییر تم برای همان مراجعه همچنان کار می‌کند.

`FAM-Operations.html` برای سازگاری با لینک پیش‌نمایش قبلی نگه داشته شده است؛ اکنون آن هم همین برنامهٔ دوتمی است، فقط در مبدأ جدید و بدون ترجیح ذخیره‌شده، با تم روشن شروع می‌شود. فایل مورد استفادهٔ اصلی **FAM.html** است. دو تم در فایل اصلی، دو مجموعه داده یا دو حساب جدا نیستند.

## نگهداری کد

```sh
python scripts/embed_ui_themes.py
python scripts/build_operations_ui.py  # فقط همگام‌سازی پیش‌نمایش سازگار قبلی
```

- `src/ui-theme.js`: اعمال زودهنگام تم، ذخیرهٔ ترجیح، کنترل‌ها و تعویض درجا.
- `src/ui-theme.css`: کنترل تغییر تم و پنهان‌کردن اجزای مخصوص تم روشن در تم اصلی.
- `src/operations-ui.css`: استایل تم روشن؛ stylesheet هنگام تم اصلی غیرفعال است.
- `src/operations-ui.js`: اجزای میزکار روشن؛ جابه‌جایی همان گره‌های فرم با حفظ حالت آن‌ها. تصویر اصلی hero حذف نمی‌شود و با برگشت به تم اصلی دوباره دیده می‌شود.
- حلقه‌های Canvas هنگام انتخاب تم روشن لغو می‌شوند و هنگام برگشت، فقط یک زنجیرهٔ انیمیشن فعال می‌شود. انتخاب پس‌زمینه و شدت آن حفظ می‌شوند.
- اصلاح ارتفاع منو بعد از تغییر تم از رویداد اختصاصی استفاده می‌کند؛ بوم گرافیکی را بی‌دلیل resize/پاک نمی‌کند.

دکمهٔ اختیاری دادهٔ نمونهٔ تم روشن همچنان فقط با اقدام صریح سطح ۱/۲ و فقط بدون شیت داده کار می‌کند؛ تغییر تم نمونه‌ای وارد نمی‌کند.

## بررسی انجام‌شده

Linux VM، Playwright و Chromium واقعی:

- **۶۵/۶۵ آزمون کامل روی تم روشن داخل فایل اصلی** در Chromium 122.0.6261.0:
  نقش‌ها، کاربران، ورود/خروج، پشتیبان، درج/حذف/بازگشت، استان/خودپرداز، ماندگاری، دسته‌بندی و نمایش واکنش‌گرا.
- **۱۱/۱۱ آزمون هدفمند روی فایل اصلی**: دو آزمون اختصاصی تعویض تم و دسترسی انتخاب تم در ورود/سطح ۴، شش آزمون UI-16 و بررسی درج/حذف سطح ۳، مسیر شعبه/خودپرداز و ایجاد کاربران.
- بررسی رابط اصلی: در اجرای گروهی ۶/۸ موفق؛ دو timeout تعامل با منو/حساب در اجرای جداگانه هر دو موفق شدند. نتیجهٔ اجرای گروهی را ۸/۸ گزارش نمی‌کنیم؛ مجموعهٔ کامل تم اصلی در این نوبت اجرا نشد.
- آزمون زندهٔ تعویض مکرر در Chromium **122.0.6261.0 و 138.0.7204.0**:
  سه پس‌زمینهٔ شبکهٔ شعب، مدار و محوطه؛ سه رفت‌وبرگشت برای هرکدام؛ در حالت روشن صفر callback انیمیشن در انتظار، در حالت اصلی عادی دقیقاً یک زنجیرهٔ فعال؛ تصویر پس‌زمینهٔ اصلی متحرک و تم روشن ثابت.
- انتخاب ذخیره‌شدهٔ روشن پس از reload بدون آغاز حلقهٔ Canvas، حفظ پیش‌نویس، رعایت reduced-motion، کارکرد هنگام خطای ذخیرهٔ ترجیح و عرض‌های ۱۴۴۰، ۸۰۰، ۳۹۰ و ۳۲۰ پیکسل بررسی شدند؛ خطای uncaught ثبت نشد.

```sh
# مجموعهٔ کامل در تم روشن، همان فایل اصلی:
FAM_THEME=light npm test

# حالت پیش‌فرض تست‌ها همچنان فایل اصلی با تم اصلی است.
# آزمون زندهٔ تعویض و حرکت، با سرور پورت 3000:
node scripts/smoke_theme_switch.cjs
```

`CHROMIUM_PATH` امکان انتخاب مرورگر نصب‌شده را می‌دهد؛ نسخهٔ ۱۲۲ استخراج‌شدهٔ این محیط به کتابخانه‌های خودش نیاز دارد. لاگ‌ها در `.cache/two-themes-*` و گزارش‌های حرکت در `test-results/two-themes-motion-*.json` هستند و طبق روال مخزن وارد Git نمی‌شوند.

این بررسی‌ها تست Windows/IIS واقعی یا همزمانی چند کاربر نیستند.
