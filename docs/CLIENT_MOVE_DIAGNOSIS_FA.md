# تشخیص فقط‌خواندنی پورت کلاینت شعب

این قابلیت در **SERVER** اضافه شده است؛ LOCAL همچنان فقط مدیریت موجودی و ابزار آفلاین دارد و SSH نمی‌زند. این بخش با بررسی/رفع Err-disabled متفاوت است و برای حالتی است که لینک Up است ولی پس از تعویض یا جابه‌جایی کلاینت، ارتباط کار نمی‌کند.

## روش استفاده

۱. وارد «تجهیزات ← بررسی پورت‌ها» شوید.
۲. یک تا پنج سوئیچ مجازِ شعبه را از فهرست بالا انتخاب کنید؛ حساب موقت SSH/RADIUS همان بخش استفاده می‌شود. شمارهٔ پورت را لازم نیست بدانید. برای حساب متفاوت، نوبت جدا اجرا کنید.
۳. در «تشخیص فقط‌خواندنی جابه‌جایی کلاینت»، IP کلاینت مانند `10.4.86.7` یا MAC آن را وارد کنید. این IP، IP سوئیچ نیست. حداقل یکی لازم است؛ MAC با قالب نقطه‌ای Cisco یا گروه‌های دوحرفی با : یا - پذیرفته می‌شود. اگر هر دو را بدهید، شواهد مرتبط با هر یک بررسی می‌شوند؛ ناسازگاری آن‌ها می‌تواند ناشی از IP تکراری باشد، نه الزاماً جابه‌جایی.
۴. «تشخیص پورت کلاینت — فقط خواندن» را بزنید. اگر انتخابی ندارید، IP دستی مجاز سوئیچ هم از فیلد موجود قابل استفاده است؛ قواعد scope همان APIهای قبلی‌اند.
۵. گزارش هر سوئیچ را جدا بخوانید. هیچ رفع یا تغییر خودکاری از این گزارش انجام نمی‌شود.

## پروفایل اولیه و IOS

پروفایل اولیه عمداً محدود است: **WS-C2960-24TT-L، VLAN 100** و قالب‌های کلاسیک IOS خانوادهٔ `12.2`، `15.0` و `15.2`. این به معنی تأیید سخت‌افزاری همهٔ نسخه‌های این خانواده‌ها نیست؛ قالب‌های قابل‌خواندن با fixture آزمایش شده‌اند. مدل و نسخه هنگام درخواست از خود تجهیز خوانده می‌شوند؛ لازم نیست کاربر از قبل شمارهٔ IOS را تایپ کند.

مرحلهٔ اول فقط فرمان‌های ثابت زیر است:

```text
terminal length 0
show version
exit
```

اگر مدل، نسخه یا نام image قابل تأیید نباشد، همان‌جا متوقف می‌شود؛ فرمان تشخیصی دیگری، تلاش دوبارهٔ خودکار یا Enable اجرا نمی‌شود. فقط مدل/نسخه/image پالایش‌شده نمایش داده می‌شوند؛ serial، اطلاعات کامل show version، banner و prompt منتشر نمی‌شوند.

مرحلهٔ دوم فقط این خواندن‌های ثابت است:

```text
terminal length 0
show port-security address
show ip source binding
show mac address-table dynamic vlan 100
show ip arp inspection log
exit
```

دو مرحله عمداً دو نشست SSH محدود هستند؛ ASKPASS بدون رمز فقط در همان درخواست یک‌بار آماده و در finally پاک می‌شود. سقف helper برابر ۸۵ ثانیه، والد ۹۵ و انتظار مرورگر برای هر سوئیچ ۱۱۰ ثانیه است. هیچ retry خودکار، فرمان ساخته‌شده از IP/MAC کاربر یا CLI آزاد وجود ندارد. `terminal length 0` فقط صفحه‌بندی همان نشست را خاموش می‌کند، نه تنظیم امنیتی دستگاه.

## معنی گزارش

- **پورت محتمل**: فقط پورت FastEthernet دسترسی `Fa0/1` تا `Fa0/24` گزارش می‌شود. Gi uplink به‌عنوان پورت مستقیم کلاینت پیشنهاد نمی‌شود.
- **MAC مشاهده‌شده**: از جدول Dynamic MAC یا سابقهٔ رد ARP مرتبط با IP/MAC مورد جست‌وجو.
- **پورت binding ثبت‌شده**: یک رکورد تنظیمی/یادگرفته‌شده است؛ لزوماً «پورت قبلی واقعی» یا «پورت فعلی» نیست.
- **اطمینان متوسط**: یک ردیف Dynamic MAC مرتبط وجود دارد. این تضمین تازگی، اتصال مستقیم تک‌دستگاه، نبود سوئیچ واسط یا جابه‌جایی نیست.
- **اطمینان کم**: فقط شواهد تاریخی DAI موجود است. زمان سوئیچ یا باقی‌ماندن رویداد در بافر، تازگی را تضمین نمی‌کند؛ گزارش آن را اتصال فعلی قطعی نمی‌نامد.
- **تعارض binding پورت/MAC یا Secure MAC**: نیازمند بررسی کارشناس است، نه مجوز پذیرش MAC تازه. وجود چند MAC مجاز، تلفن/سوئیچ واسط، IP تکراری یا اتصال غیرمجاز باید جدا بررسی شوند.
- **منبع غیرقابل‌تأیید**: فرمان پشتیبانی نشده، مجوز کافی نبوده، جدول ناقص/ناشناخته بوده یا header/ردیف‌ها قابل تجزیه نبوده‌اند. این وضعیت «خالی و سالم» حساب نمی‌شود.
- **پورت نامشخص**: نبود ترافیک، بسته‌بودن مسیر یادگیری MAC، DAI غیرفعال/بدون لاگ، buffer قدیمی/خالی یا نبود شواهد کافی. نبود شواهد ثابت نمی‌کند جابه‌جایی رخ نداده است.

هیچ نتیجه‌ای `movementConfirmed=true` یا «اطمینان بالا/جابه‌جایی قطعی» اعلام نمی‌کند. در حالت دادهٔ مبهم چند کاندید ممکن است نشان داده شود؛ اولویت ظاهری، اثبات انتخاب پورت نیست. تصویر کامل ARP ACL یا وضعیت اجرایی IPSG در این نسخه خوانده نمی‌شود؛ بنابراین گزارش، علت قطعی مسدودشدن یا تطابق کامل ACL را ادعا نمی‌کند.

## چه چیزی تغییر نمی‌کند؟

این قابلیت **هیچ‌کدام** از موارد زیر را انجام نمی‌دهد:

- حذف/یادگیری اجباری Sticky MAC؛
- تغییر `ip verify source port-security`؛
- تغییر `ip source binding` یا ARP ACL؛
- shutdown / no shutdown، clear، Enable، ذخیرهٔ کانفیگ یا پذیرش خودکار MAC تازه؛
- درخواست رفع، تولید ticket رفع یا فعال‌سازی پورت administratively disabled.

برای اصلاح واقعی اتصال، تشخیص هویت و مجوز جابه‌جایی و تصمیم کارشناس لازم است. از گزارش تشخیص نمی‌توان دکمهٔ رفع Err-disabled را برای پورت Up یا نامشخص فعال کرد. اگر کاربر جابه‌جایی را اعلام نکرده، صرف مشاهدهٔ MAC تازه به معنی مجازبودن آن نیست.

## امنیت و نگهداری اطلاعات

همان نشست FAM، Origin، CSRF، مجوز مستقل equipment-scan، دسترسی ورود تجهیزات و پنج scope اعمال می‌شوند. روتر شناخته‌شده رد می‌شود؛ IP دستی خارج موجودی فقط با wildcard هر پنج scope مجاز است. قفل مشترک هر IP و سقف دو عملیات سرور شامل این خواندن نیز می‌شود.

IP/MAC ورودی فقط دادهٔ درخواست‌اند و در رشتهٔ CLI وارد نمی‌شوند. credential، گزارش، شواهد، IP/MAC جست‌وجوشده و نتیجه در DB، history، workbook، URL یا browser storage نوشته نمی‌شوند. فقط RAM سند جاری؛ refresh/logout/تغییر هویت پاک می‌کند. تغییر credential، انتخاب سوئیچ یا ورودی جست‌وجو نتیجهٔ قبلی را نامعتبر می‌کند. جابه‌جایی تب به‌تنهایی credential را پاک نمی‌کند. نمایش با textContent است، نه HTML خام.

هر جدول حداکثر ۴۰۹۶ ردیف و خروجی تشخیصی حداکثر ۵۱۲ KiB دارد؛ گزارش حداکثر ۴۸ کاندید است و عبور از سقف، نامشخص می‌شود. مرز فرمان‌ها باید دقیقاً قابل تشخیص باشد؛ parser با حدس، متن‌های چند فرمان را به هم نسبت نمی‌دهد. خروجی خام به مرورگر نمی‌رسد؛ استثنای raw جدول show int des مربوط به مسیر جداگانهٔ قبلی است.

## نصب و آزمون

از **پچ SERVER جدید همین نوبت** با ۲۲ فایل payload استفاده کنید؛ کپی‌کردن فقط HTML کافی نیست. module جدید `equipment_diagnostics.py` همراه helper/API/UI لازم است. راهنمای نصب، known_hosts تأییدشده و بازگشت کد: [SERVER_REVIEW_FIX_PATCH_FA.md](SERVER_REVIEW_FIX_PATCH_FA.md).

تست‌های این قابلیت با مدل/خروجی و SSH ساختگی انجام شده‌اند. روی سوئیچ واقعی، IOS واقعی شعبه، Windows ASKPASS و IIS استقرار شما اجرا نشده است. ابتدا روی محیط تست مجاز، فقط دکمهٔ خواندن را امتحان کنید. اگر پروفایل یا جدول ناشناخته بود، خطا را با حذف محافظت‌ها، Enable یا فرمان آزاد دور نزنید؛ شمارهٔ IOS/image و قالب جدولِ پالایش‌شده باید برای توسعهٔ پشتیبانی بررسی شوند، نه رمز، serial یا کانفیگ کامل.

## مسیر جدید وقتی کارشناس پورت را می‌داند
تشخیص فقط‌خواندنی فوق همچنان اختیاری است. برای تعویض MAC با IP بدون تغییر، پورت و تیک IP دستی کنار همان سوئیچ را به کار ببرید؛ پیش‌نمایش و تأیید مستقل دارد. راهنما: `CLIENT-MAC-REPLACEMENT-FA.txt` داخل ZIP یا `docs/CLIENT_MAC_REPLACEMENT_FA.md`. Sticky قبلی بدون مجوز جداگانه حذف نمی‌شود.
