# پنل عملیات شبکه — رفع Err-Disable

> وضعیت: این قابلیت در سورس FAM آماده و **به‌صورت پیش‌فرض خاموش** است. هیچ تغییری روی سرور عملیاتی انجام نشده است. ابتدا فقط روی VM آزمایشی اجرا و پذیرش شود.

کاربر FAM فقط با مرورگر به داشبورد مرکزی وصل می‌شود. مرورگر او نه SSH باز می‌کند، نه رمز تجهیز را نگه می‌دارد و نه امکان ارسال فرمان دلخواه دارد. پس از ورود، مدیر سطح ۱ یا اپراتور سطح ۲ کارت **«عملیات شبکه / رفع Err-Disable»** را می‌بیند؛ سطح ۳ و ۴ اصلاً این کارت یا API آن را ندارند.

## عملیات فعلی

نسخهٔ فعلی فقط یک دستورکار محدود Cisco-style را اجرا می‌کند:

1. اپراتور نوع تجهیز، IPv4، نام کاربری، رمز عبور، نام اینترفیس و اثرانگشت کلید SSH تجهیز را وارد و تأیید صریح می‌کند.
2. سرویس FAM روی **خود سرور** به SSH پورت ۲۲ تجهیز وصل می‌شود؛ هیچ اتصال مستقیمی از رایانهٔ کاربر ساخته نمی‌شود.
3. ابتدا `show interfaces <interface> status` را می‌خواند. اگر `err-disabled` دیده نشود، **هیچ فرمان پیکربندی** ارسال نمی‌شود.
4. فقط در صورت مشاهدهٔ Err-Disable این دنبالهٔ ثابت اجرا می‌شود:

   ```text
   terminal length 0
   show interfaces <interface> status
   configure terminal
   interface <interface>
   shutdown
   no shutdown
   end
   show interfaces <interface> status
   ```

5. `enable` ارسال نمی‌شود؛ Router با نام کاربری/رمز RADIUS واردشده توسط اپراتور و Switch با حساب محلی واردشده توسط اپراتور کار می‌کند. `write memory` یا هر ذخیره‌سازی `startup-config` هم اجرا نمی‌شود.

بنابراین رابط ممکن است چند لحظه رابط را قطع و وصل کند. علت اصلی Err-Disable (مثلاً port-security، loop یا BPDU Guard) باید جداگانه توسط تیم شبکه بررسی شود؛ اگر علت پابرجا باشد، خروجی پس از فرمان همچنان `err-disabled` را نشان می‌دهد.

## کنترل‌های امنیتی

- IPv4 باید داخل CIDRهای صریحِ تعریف‌شده برای سرویس باشد. این محدودیت مانع تبدیل پنل به SSH/SSRF عمومی می‌شود.
- نام اینترفیس با الگوی محدود Cisco اعتبارسنجی می‌شود؛ newline، `;`، فرمان دوم و فرمان دلخواه پذیرفته نمی‌شود.
- کلید SSH تجهیز با اثرانگشت `SHA256:…` که اپراتور وارد می‌کند تطابق داده می‌شود. اثرانگشت را از مسیر مورد اعتماد تیم شبکه بگیرید؛ هشدار کلید ناشناخته/تغییرکرده را تأیید نکنید.
- رمز و نام کاربری تجهیز فقط در حافظهٔ همان درخواست HTTPS/SSH هستند. در SQLite، تاریخچه، خروجی عملیات و لاگ برنامه ذخیره یا نمایش داده نمی‌شوند.
- برای جلوگیری از دوباره‌اجرای ناخواسته در قطع پاسخ مرورگر، هر درخواست یک شناسهٔ یکتا دارد و نتیجهٔ همان درخواست تکراری برگردانده می‌شود. برای هر اپراتور سقف پنج عملیات در هر دقیقه وجود دارد.
- تاریخچهٔ قابل‌مشاهده شامل اپراتور FAM، زمان، IP، نوع تجهیز، اینترفیس، وضعیت و خروجی کوتاه‌شدهٔ فرمان است؛ نه رمز یا نام کاربری تجهیز.

## فعال‌سازی فقط روی VM آزمایشی

پیش‌نیازهای شبکه‌ای را تیم شبکه روی VM بررسی کند:

- خود VM سرویس FAM باید به IPv4های مجاز و TCP/22 تجهیزات مسیر داشته باشد.
- ارتباط از ایستگاه کاربران به تجهیزات لازم نیست و نباید جایگزین مسیر VM شود.
- VM باید نسخهٔ به‌روزشدهٔ FAM و وابستگی `paramiko==5.0.0` را داشته باشد. برای نصب آفلاین، `PREPARE-OFFLINE.cmd` را دوباره اجرا کنید تا ۲۰ wheel پین‌شدهٔ فعلی آماده شوند.

در نصب/به‌روزرسانی دستی، فعال‌سازی فقط با هر دو پارامتر انجام می‌شود. نمونهٔ زیر صرفاً نمونه است؛ CIDR واقعی و حداقلی تیم شبکه را جایگزین کنید:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\FAM\server\windows\install.ps1 `
  -PublicOrigin 'https://your-fam-host.example.internal' `
  -DataDir 'C:\FAMData' `
  -EnableNetworkOperations `
  -DeviceNetworks '10.20.0.0/16,10.21.7.0/24'
```

پارامتر `-DeviceNetworks` اجباری است. بدون آن، فعال‌سازی متوقف می‌شود؛ بدون `-EnableNetworkOperations` نیز کارت فقط پیام «در تنظیمات سرویس فعال نشده» نشان می‌دهد. تنظیم ذخیره‌شده در فایل خصوصی `C:\FAM\server\windows\settings.json` قرار می‌گیرد و در به‌روزرسانی عادی حفظ می‌شود.

## پذیرش VM

1. با یک حساب سطح ۱ یا ۲ به URL HTTPS VM وارد شوید و کارت عملیات شبکه را ببینید.
2. با حساب سطح ۳ یا ۴ بررسی کنید که کارت و endpoint قابل‌دسترسی نیست.
3. یک IP خارج از CIDR تعریف‌شده، نام اینترفیس دارای newline یا تأییدنشده را امتحان کنید؛ باید پیش از SSH رد شود.
4. روی تجهیز/اینترفیس آزمایشی که واقعاً Err-Disable است، اثرانگشت صحیح را وارد و نتیجهٔ قبل/بعد را با CLI مستقل تیم شبکه تطبیق دهید.
5. اثرانگشت نادرست را امتحان کنید؛ باید اتصال رد و هیچ فرمان پیکربندی اجرا نشود.
6. در لاگ خصوصی و جدول عملیات تأیید کنید رمز/نام کاربری تجهیز وجود ندارد. سپس Restart سرویس را امتحان و تاریخچه را بررسی کنید.

این سند اجازهٔ تغییر سرور عملیاتی نیست. پس از پذیرش VM، قبل از هر استقرار عملیاتی باید بازبینی شبکه، محدودهٔ CIDR، اثرانگشت‌های تجهیزات و پنجرهٔ تغییر جداگانه تأیید شود.
