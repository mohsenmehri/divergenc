# نصب آفلاین فام — Windows Server 2019 x64

مقصد: **10.16.243.18** — آدرس کاربران: **https://ertebatat-fam**.

این انتشار، اصلاح تم ۲ (منوی روشن، مخفی‌بودن کنترل‌های پس‌زمینه و سفیدماندن فیلدها هنگام کلیک/فوکوس) را هم دارد. بعد از این نصب، HTML اصلاح‌شده خودکار در `C:\FAM\server\www\FAM.html` قرار می‌گیرد.

## دقیقاً چه چیزهایی باید ببری؟

**ZIP این انتشار از ابتدا همهٔ wheelهای Python لازم را دارد، اما سه نصب‌کنندهٔ بزرگ زیر داخل ZIP اولیه نیستند.** قبل از انتقال، آنها را اضافه کن. بدون این سه فایل، نصب‌کننده قبل از تغییر سرور متوقف و نام فایل‌های کم‌شده را اعلام می‌کند؛ روی سرور دانلود نمی‌کند.

| مورد | فایل با همین نام | دریافت رسمی |
|---|---|---|
| Python کامل x64 نسخهٔ 3.14.7؛ نه نصب‌کنندهٔ کوچک اینترنتی/Store | `python-3.14.7-amd64.exe` | [Python.org](https://www.python.org/ftp/python/3.14.7/python-3.14.7-amd64.exe) |
| IIS URL Rewrite x64 | `rewrite_amd64_en-US.msi` | [Microsoft](https://download.microsoft.com/download/1/2/8/128E2E22-C1B9-44A4-BE2A-5859ED1D4592/rewrite_amd64_en-US.msi) |
| IIS Application Request Routing 3 x64 | `requestRouter_amd64.msi` | [Microsoft ARR](https://go.microsoft.com/fwlink/?LinkID=615136) |

هر سه را کنار هم در این مسیر **داخل پوشهٔ استخراج‌شدهٔ بسته** بگذار:

```text
server\windows\payload\
```

نام فایل ARR را اگر مرورگر با نام دیگری ذخیره کرد، مطابق جدول بگذار؛ محتوا باید با SHA256 ثبت‌شده تطبیق داشته باشد. نسخه‌های تصادفی دیگر یا بسته‌های دانلودشده از سایت‌های متفرقه جایگزین نشوند.

### راه ساده‌تر: جمع‌آوری خودکار روی کامپیوتر اینترنت‌دار

1. بستهٔ `FAM-Central-IIS.zip` را **روی کامپیوتر ویندوزی اینترنت‌دار** کامل استخراج کن.
2. **`PREPARE-OFFLINE.cmd`** را اجرا کن. این مرحله **نه Python می‌خواهد، نه Administrator و نه چیزی روی آن کامپیوتر نصب می‌کند**؛ فقط سه فایل رسمی را دریافت می‌کند، SHA256 و امضای ناشر را بررسی می‌کند و wheelهای موجود را کنترل/در صورت نبود دریافت می‌کند.
3. فقط پس از پیام **`OFFLINE KIT READY`**، **کل پوشهٔ استخراج‌شده** را به سرور منتقل کن. ZIP اولیه را دوباره کپی نکن؛ دانلودها به آن ZIP اضافه نشده‌اند، بلکه داخل پوشهٔ استخراج‌شده‌اند. می‌توانی خودت کل پوشهٔ تکمیل‌شده را مجدداً ZIP کنی.

اگر دریافت خودکار به علت محدودیت اینترنت کامپیوتر انجام نشد، سه فایل جدول را دستی تهیه و در مسیر گفته‌شده بگذار. تمام wheelهای لازم از قبل در ZIP این انتشار موجودند؛ نیازی به `pip download` دستی نیست.

### محتوای مورد انتظار هنگام انتقال

```text
FAM-Setup\

  docs\...
  server\

        requestRouter_amd64.msi

```

کتابخانه‌های همراه: Flask 3.1.3، waitress 3.0.2، Werkzeug 3.1.9، Jinja2 3.1.6، MarkupSafe 3.0.4، itsdangerous 2.2.0، click 8.5.0، blinker 1.9.0 و colorama 0.4.6. سه wheel مجزای MarkupSafe برای CPython 3.12/3.13/3.14 x64 وجود دارد؛ بقیه مشترک‌اند. SQL Server، Node.js، Office و Python جداگانه روی سرور لازم نیست؛ SQLite همراه Python است.

## فایل منبع Windows؛ فقط اگر قابلیت‌های IIS ناقص باشند

چون IIS از قبل نصب است، ممکن است هیچ فایل سیستم‌عامل اضافی لازم نباشد. با این حال **رسانه/ISO معتبر همان Windows Server 2019، مطابق Edition، زبان، نوع نصب و سطح به‌روزرسانی موردنیاز سرور** را در دسترس مدیر داشته باش؛ به‌خصوص اگر payload قابلیت `IIS-ManagementScriptingTools` یا قابلیت‌های دیگر از WinSxS حذف شده باشد. ISO ویندوز داخل بسته نیست و نسخهٔ تصادفی Windows 10/Server 2022 جایگزین آن نیست.

نصب‌کننده ابتدا از فایل‌های موجود خود Windows استفاده می‌کند. اگر منبع کم باشد، با پیام مشخص متوقف می‌شود؛ **به Windows Update متصل نمی‌شود**. برای معرفی منبع آفلاین، مدیر می‌تواند ISO را Mount کند و کنار `INSTALL-FAM.cmd` فایل متنی **`WINDOWS-FEATURE-SOURCE.txt`** بسازد. محتوا فقط یک خط مسیر منبع باشد.

مثلاً اگر ISO روی `D:` است، ابتدا indexهای واقعی را ببیند:

```powershell
Dism.exe /Get-WimInfo /WimFile:D:\sources\install.wim
```

پس از انتخاب index **مطابق سیستم‌عامل سرور**، در فایل متنی بنویسد `WIM:D:\sources\install.wim:N` و **N را با شمارهٔ واقعی همان image جایگزین کند**. اگر مدیر منبع معتبر SxS/WinSxS متناظر آماده کرده، مسیر همان منبع را می‌تواند بدهد. index ثابت و حدسی در نصب‌کننده انتخاب نشده است. سپس `INSTALL-FAM.cmd` را دوباره اجرا کند. عبارت `-Online` در دستور DISM به معنی «Windows در حال اجرا» است، نه اینترنت؛ `-LimitAccess` مانع مراجعه به Windows Update می‌شود.

## اجرا روی سرور

1. Snapshot ماشین مجازی یا بکاپ مناسب داشته باش؛ نصب نخست در زمان نگهداری انجام شود. خود نصب‌کننده هنوز روی Windows/IIS واقعی در این محیط آزموده نشده است.
2. پوشهٔ تکمیل‌شده را مثلاً در `C:\FAM-Setup` روی **10.16.243.18** قرار بده.
3. **`INSTALL-FAM.cmd`** را اجرا و Administrator/UAC را تأیید کن. حالت پیش‌فرض این انتشار **آفلاین** است؛ وجود یا نبود فایل نشانگر، آن را به آنلاین تبدیل نمی‌کند.
4. گواهی موجود اگر دارای SAN مناسب `ertebatat-fam` و معتبر باشد استفاده می‌شود. در غیر این صورت ساخت گواهی جدید فقط با تأیید انجام می‌شود. نسخهٔ فعلی certificate را با binding دقیق SNI یعنی `10.16.243.18:443:ertebatat-fam` متصل و دوباره می‌خواند تا گواهی IP-only سایت دیگر پاسخ داده نشود. IIS authentication موجود بدون تأیید جداگانه عوض نمی‌شود. DNS، IP و قوانین فعلی فایروال/GPO خودکار بازنویسی نمی‌شوند.
5. برنامه فقط پس از کنترل HTTPS و API و بکاپ اولیه، موفقیت را اعلام می‌کند. گزارش خصوصی در `C:\FAMData\logs` است. در صورت درخواست reboot، مدیر در زمان مناسب reboot و همان فایل را مجدد اجرا کند؛ reboot اجباری/خودکار انجام نمی‌شود.

اگر نصب قبلاً انجام شده و فقط اصلاح ظاهر می‌خواهی، به جای نصب مجدد می‌توانی تنها `server\www\FAM.html` این بسته را جایگزین فایل `C:\FAM\server\www\FAM.html` کنی. به دیتابیس و تنظیمات سرور دست نزن. کاربران پس از ثبت تغییرات باز، Ctrl+F5 بزنند.

## گواهی، نام داخلی و محدودیت آفلاین

- به اینترنت عمومی برای استفادهٔ روزمره نیاز نیست؛ کاربران با همان شبکهٔ داخلی به `https://ertebatat-fam` وصل می‌شوند. نام باید در DNS داخلی به **10.16.243.18** برسد؛ صرف تعیین IP در نصب‌کننده رکورد DNS نمی‌سازد.
- اعتماد گواهی self-signed روی کاربران همچنان لازم است. روش کنترل‌شدهٔ توزیع **فقط** پوشهٔ `C:\FAMData\client-setup` در [راهنمای اصلی](AUTO_INSTALL_FAM_FA.md) آمده است. کل FAMData را Share نکن.
- روی کامپیوتر اینترنت‌دار، `PREPARE-OFFLINE.cmd` برای هر سه نصب‌کننده، SHA-256 و امضای ناشر با status=`Valid` را الزام می‌کند. روی سرور کاملاً جدا از اینترنت، Windows ممکن است فقط به علت ناتوانی در دسترسی به زنجیره/ابطال گواهی، status `UnknownError` یا `NotTrusted` گزارش دهد. در نسخهٔ آفلاین، تنها همین دو status **و فقط پس از تطبیق SHA-256 پین‌شده و وجود امضاکنندهٔ embedded با ناشر مورد انتظار** اجازهٔ ادامه می‌گیرند و هشدار ثبت می‌شود. فایل بدون امضا، دارای امضای مخدوش، ناشر متفاوت، status دیگر یا هش متفاوت هرگز اجرا نمی‌شود. گواهی ریشهٔ ناشناس وارد و TLS خاموش نمی‌شود. اگر سازمان می‌تواند زنجیره را از WSUS/سیاست اعتماد تأمین کند، نتیجهٔ `Valid` همچنان حالت ترجیحی است.
- برای این نسخه **Windows Server 2019 x64** هدف است؛ نبود Python/ARR/Rewrite مشکلی ذاتی نیست چون نصب‌کننده‌های کاملشان را همراه می‌بری. اما نبود فایل منبع Windows، سیاست امنیتی محدودکننده یا reboot معوق ممکن است نیازمند اقدام مدیر باشد؛ تضمین «بدون خطا روی هر سرور» داده نمی‌شود.

## آزمون‌های این انتشار

wheelها با SHA256 اطلاعات PyPI تطبیق داده شده‌اند و حل وابستگی برای هر سه Python 3.12/3.13/3.14 با `--no-index` فقط از فایل‌های محلی بررسی می‌شود. این بررسی معادل نصب/اجرای Windows نیست. آزمون‌های UI، API و محدودیت‌های اجرایی در [گزارش این انتشار](OFFLINE_UPDATE_TEST_REPORT.md) ثبت شده‌اند.
