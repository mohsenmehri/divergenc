# گزارش آزمون نصب‌کنندهٔ خودکار فام

> این گزارش مربوط به انتشار اولیهٔ نصب‌کننده است. برای تغییرات جدید، wheelهای همراه و نتایج آفلاین، [گزارش به‌روزرسانی](OFFLINE_UPDATE_TEST_REPORT.md) را ببینید.

تاریخ: 2026-10-11 — هدف پیکربندی: `10.16.243.18` / `https://ertebatat-fam`.

## واقعاً اجرا شده

محیط اجرا Linux و Python 3.11.2 است، نه Windows سرور مشتری.

- `python -m unittest server.tests.test_installer server.tests.test_api`: **29/29 موفق**، آخرین اجرا **9.944 ثانیه**.
  - 21 آزمون موجود API/مجوزها/هم‌زمانی/بکاپ و بازیابی دوباره اجرا شد.
  - 8 آزمون نصب‌کننده: بکاپ از دیتابیس دارای WAL باز با حفظ حساب‌ها؛ جلوگیری از بازنویسی بکاپ؛ رد دیتابیس نامرتبط؛ اتصال HTTPS واقعی محلی به Flask با گواهی موقت SANدار و کنترل API بدون تغییر workbook/حساب‌ها؛ رد نام نادرست؛ رد گواهی غیرمورداعتماد؛ رد گواهی فقط CN و فاقد SAN؛ کنترل تنظیم PassThrough خطاهای API در XML مربوط به IIS.
- `node --test tests/shared-build.test.cjs`: **3/3 موفق**؛ اتصال نسخهٔ مرکزی، عدم تغییر هندسهٔ تم روشن و عدم تغییر بایت‌های XLSM.
- هشت فایل PowerShell (هفت فایل عملیاتی/ماژول و یک آزمون Windows) با **tree-sitter-powershell 0.26.4** بررسی نحوی شدند؛ خطای parse ثبت نشد. **این parser جای اجرای Windows PowerShell 5.1 یا آزمایش cmdletهای IIS را نمی‌گیرد.**
- گزارش انتشار اولیه، بستهٔ 25 فایلی با فهرست مجاز را پوشش می‌داد. در به‌روزرسانی آفلاین بعدی، 32 wheel هش‌شدهٔ Python نیز عمداً داخل ZIP قرار گرفتند؛ سه نصب‌کنندهٔ رسمی Python/Rewrite/ARR باید با `PREPARE-OFFLINE.cmd` روی کامپیوتر اینترنت‌دار افزوده شوند. دیتابیس واقعی، settings فعال، کلید خصوصی و `.venv` همچنان داخل بسته نیستند؛ جزئیات و آزمون جدید در `OFFLINE_UPDATE_TEST_REPORT.md` است.

## اجرا نشده / محدودیت مهم

- **این نصب‌کننده روی Windows/IIS واقعی یا سرور 10.16.243.18 اجرا نشده است.** پیکربندی واقعی سایت فعلی، گواهی آن و نسخهٔ Windows در این محیط قابل مشاهده نیست.
- نصب MSI/EXE، UAC، Task Scheduler، ACL، SNI/ARR در Windows، آماده‌سازی آفلاین روی Windows و نصب اعتماد در کامپیوتر کاربران هنوز آزمون اجرایی نشده‌اند.
- کد آزمون قابل اجرا روی یک Windows آزمایشیِ دورریختنی در `tests/windows-installer.ps1` اضافه شده است: parse بومی، نصب IIS واقعی، HTTPS/API، نصب مجدد، حفظ داده/credentialها و ثابت‌ماندن سایت نامرتبط. **روی سرور تولید اجرا نکنید**؛ خودش محیط تست و hosts آزمایشی ایجاد می‌کند.
- ثبت workflow برای اجرای خودکار آن در GitHub با محدودیت مجوز `workflows` اتصال فعلی روبه‌رو شد؛ **هیچ اجرای Windows CI موفقی ادعا نمی‌شود**. نمونهٔ غیرفعال در `tests/windows-installer-workflow.yml.example` است؛ مدیر مخزن می‌تواند جداگانه آن را فعال کند. نمونه/آزمون Windows جزو ZIP اجرایی کاربر نیستند.
- آزمون HTTPS محلی بالا، IIS/ARR را شبیه‌سازی نمی‌کند. کنترل XML صرفاً اطمینان از وجود تنظیم است، نه اثبات رفتار IIS واقعی.
- هیچ آزمایش پنج کامپیوتر فیزیکی، GPO/DNS سازمان یا دسترسی از VLAN کاربران انجام نشده است. گزارش قبلی پنج مرورگر مستقل روی یک میزبان Linux در [SHARED_TEST_REPORT.md](SHARED_TEST_REPORT.md) باقی است؛ در این مرحله آن آزمون مرورگر مجدداً اجرا نشده است.

## مرز ایمنی و موفقیت

- تطبیق IP با سرور محلی، عدم تصاحب Task متعلق به نصب دیگر، جلوگیری از جایگزینی دیتابیس گم‌شده با دیتابیس خالی، رد مسیرهای junction/symlink و جداسازی فایل عمومی از دادهٔ خصوصی در کد لحاظ شده‌اند؛ صحت اجرایی ACLهای Windows باید روی مقصد تأیید شود.
- نصب‌کننده روی مقصد فقط پس از بررسی HTTPS با نام/SAN درست، همان گواهی انتخاب‌شده، صفحهٔ مرکزی، پاسخ JSON احراز هویت و مسیر POST API موفقیت اعلام می‌کند. TLS verification خاموش نمی‌شود و برای تست از رمز واقعی کاربر استفاده نمی‌شود. یک تلاش ناموفق ورودِ مصنوعی ممکن است در جدول محدودسازی ورود ثبت شود؛ workbook و حساب‌ها تغییر نمی‌کنند.
- نصب‌کننده‌های رسمی از URLهای ثبت‌شده در `server/windows/dependencies.json` خوانده می‌شوند؛ SHA256 از manifestهای رسمی مخزن `microsoft/winget-pkgs` دریافت شده است. باینری‌های Microsoft/Python در این محیط دریافت/اجرا نشده‌اند؛ اسکریپت مقصد پیش از اجرای آنها SHA256 و Authenticode ناشر را کنترل می‌کند.
- نصب Feature/ماژول‌های مشترک و فعال‌سازی ARR می‌تواند اثر سراسری داشته باشد؛ «عدم حذف سایت دیگر» به معنی تضمین نبود وقفهٔ سرویس در نصب پیش‌نیازها نیست. rollback کامل Windows/IIS تضمین نشده است.

## پذیرش روی مقصد، قبل از استفادهٔ عمومی

1. اجرای نصب در زمان نگهداری و مشاهدهٔ گزارش واقعی HTTPS/API؛ بررسی نام سایت و گواهی در `deployment.json`.
2. اعتماد گواهی و resolve نام روی هر کامپیوتر؛ بازشدن صفحه بدون هشدار TLS و بدون خطای ارتباط API.
3. ورود با حساب‌های جداگانه، مشاهدهٔ تغییر یک کاربر توسط دیگری و بررسی محدودیت سطوح 3 و 4.
4. تأیید شروع `FAM-Central` پس از راه‌اندازی مجدد واقعی Windows؛ بررسی Last Run Result کار بکاپ، فایل و گزارش بکاپ؛ یک بازیابی آزمایشی روی محیط جداگانه.
5. تأیید دسترسی‌نداشتن کاربران عادی/IIS به `FAMData` و نداشتن اجازهٔ نوشتن کد سرویس، و نگه‌داشتن بکاپ محافظت‌شده خارج از همین سرور.
