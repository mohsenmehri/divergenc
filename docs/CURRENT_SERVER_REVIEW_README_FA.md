# سورس نسخهٔ فعلی SERVER برای بررسی — اولویت Python تجهیزات

این بسته جایگزین بستهٔ بررسی قبلی است. تمرکز اول بررسی روی `server/equipment_probe.py`، `server/equipment_ops.py` و اتصالشان به inventory، مجوزهای app و رابط مرورگر است. بقیهٔ SERVER نیز برای بررسی کامل داخل بسته است. از `REVIEW_PROMPT_FA.md` برای هر بازبین، با شناسهٔ مستقل A/B/C استفاده کنید.

## این بسته دقیقاً کدام نسخه است؟

سورس فعلی پروژه و آخرین پچ SERVER موجود در مخزن است. ما به فایل‌های سرور عملیاتی دسترسی نداریم و این بسته export آن سرور نیست؛ بدون مقایسهٔ hash فایل‌های نصب‌شده نمی‌توان ادعا کرد نصب واقعی دقیقاً همین نسخه است. مرجع سورس در `SOURCE_REVISION.txt` و hash تک‌فایل‌ها در `SHA256SUMS.txt` است. این تحویل هیچ کد اجرایی برنامه را تغییر نمی‌دهد.

## محتوا

- همهٔ فایل‌های ثبت‌شدهٔ `server/`: پایتون، UI محافظت‌شدهٔ فعلی، www عمومی، requirements، Windows/IIS، backup/restore و تست‌ها.
- `src/` برای خواندن source رابط و دنبال‌کردن call chain، همراه FAM.html ریشه به‌عنوان ورودی build؛ UI نهایی SERVER فایل `server/private_ui/FAM.html` است، نه FAM.html ریشه.
- پچ فعلی `releases/FAM-Custom-Access-SERVER-Patch.zip` و سورس همان پچ در `patches/fam-custom-access-server/` برای تطبیق updater و payload با backend.
- اسکریپت‌های مرتبط build/بسته‌بندی/آماده‌سازی آفلاین، تست‌های رابط، مستندات منتخب مرتبط با SERVER و تجهیزات، package.json و lockfile.
- راهنما و پرامپت مخصوص همین بررسی در ریشهٔ ZIP. هیچ پروژهٔ تبدیل یا پیاده‌سازی جایگزین در این بسته قرار ندارد.

## ایمنی و محرمانگی

بسته برای code review است، نه کیت آفلاین آمادهٔ نصب. دیتابیس، backup، لاگ، تنظیمات runtime، known_hosts، کلید خصوصی، فایل رمز، wheel، نصب‌کنندهٔ باینری، venv، node_modules، workbook اصلی XLSM و screenshotها کپی نشده‌اند. سورس، HTML و مستندات موجود پروژه ممکن است نام، دامنه، IP نمونه/سازمانی و مقدار bootstrap یا fixture داشته باشند؛ این بسته anonymized نیست. فقط به افراد مورداعتماد بدهید و اطلاعات واقعی ورود یا دادهٔ حساس به آن اضافه نکنید.

## بررسی و تست

ابتدا README و پرامپت، سپس کد و تست را بخوانید. برای بررسی نباید installer اجرا شود یا به دستگاه واقعی وصل شوید. در محیط ایزوله و با دادهٔ ساختگی، فرمان تست بخش اصلی از ریشهٔ بسته:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r server/requirements.txt
python -m unittest server.tests.test_api server.tests.test_equipment_probe server.tests.test_equipment_ops server.tests.test_equipment_inventory server.tests.test_hardening -v
```

تست‌های فوق از test client، DB موقت و executor/SSH mock استفاده می‌کنند. موفقیت آن‌ها تأیید رفتار Windows OpenSSH، RADIUS، IIS، fingerprint یا سازگاری cipher روی سخت‌افزار نیست. تست‌های تاریخی دیگر ممکن است به artifactها یا workbookهایی وابسته باشند که عمداً داخل بسته نیستند؛ missing artifact را به‌عنوان محدودیت اجرا ثبت کنید، نه نتیجهٔ بررسی runtime. برای JS نیز وابستگی‌های package-lock و محیط مرورگر لازم است.

هنگام تحویل این بسته، همین فرمان از ZIP استخراج‌شده اجرا شد: **۹۶ تست موفق**. هیچ تماس با تجهیز واقعی یا نصب/تغییر روی سرور انجام نشده است. بازبین باید نتیجهٔ مستقل خودش را ثبت کند.

## بازگرداندن نظرها

هر سه نفر همین فایل یکسان را مستقل بررسی کنند؛ گزارش نفر قبلی را پیش از پایان بررسی به دیگری ندهید. گزارش‌ها را جدا با شناسهٔ A/B/C و تمام شواهد/مسیر فایل/تست بازتولید برگردانید. قبل از تغییر کد، هر یافته باید با این نسخهٔ مرجع تطبیق داده شود؛ رأی اکثریت به‌تنهایی اثبات درست یا غلط بودن یک ایراد نیست.
