# نصب خودکار فام روی سرور 10.16.243.18

> **به‌روزرسانی آفلاین Windows Server 2019:** مسیر نصب پیش‌فرض اکنون آفلاین است. ابتدا [راهنمای انتقال پیش‌نیازها](OFFLINE_SERVER_2019_FA.md) را انجام دهید؛ 11 wheel داخل ZIP و سه نصب‌کننده نیازمند افزودن روی کامپیوتر اینترنت‌دارند.

**آدرس موردنظر کاربران: `https://communication-02.toosbank.corp`**

این بسته برای نصب مرکزی روی Windows Server x64 با Windows PowerShell 5.1 ساخته شده است؛ برنامهٔ دوتِمی همان نسخهٔ منتخب است و شکل/چیدمان تم روشن تغییر نکرده است. نصب روی سرور واقعی شما از این محیط انجام نشده است. آزمون‌های فعلی و محدودیت آزمایش Windows در [گزارش نصب‌کننده](AUTO_INSTALL_TEST_REPORT.md) آمده‌اند.

## اجرای معمول: یک فایل روی سرور

1. فایل `FAM-Central-IIS.zip` را **کامل** در پوشه‌ای مانند `C:\FAM-Setup` استخراج کنید؛ داخل ZIP اجرا نکنید. قبل از شروع روی سرور اشتراکی، زمان مناسب نگهداری و بکاپ مستقل داشته باشید.
2. **روی خود سرور 10.16.243.18**، فایل **`INSTALL-FAM.cmd`** را اجرا و درخواست Administrator/UAC را تأیید کنید. این مرحله را مدیر سرور انجام می‌دهد؛ پنج کاربر لازم نیست به سرور RDP بزنند.
3. اگر گواهی فعلی معتبر، دارای کلید خصوصی و دارای **SAN برابر `communication-02.toosbank.corp`** باشد، نصب‌کننده از آن استفاده می‌کند. اگر چند گواهی مناسب موجود باشد، شماره می‌پرسد. صرفِ اختصاص گواهی به وب‌سایت کافی نیست؛ گواهی مخصوص IP یا نام دیگری برای این آدرس معتبر نیست. در نبود گواهی مناسب، فقط با تأیید `YES` گواهی جدید مخصوص فام می‌سازد؛ گواهی‌های دیگر حذف نمی‌شوند.
4. اگر وب‌سایت اختصاصی همین نام از قبل موجود باشد، برای تغییر مسیر آن تأیید می‌گیرد؛ سایت دارای برنامه‌های فرعی یا آدرس‌های نامرتبط را خودکار تصاحب نمی‌کند. اگر سایت فعلی فقط HTTPS بدون Host name دارد، معمولاً سایت جداگانهٔ SNI برای نام فام ساخته می‌شود.
اگر سایت فعلی یا تنظیمات سراسری IIS احراز هویت Windows/Basic را الزامی کرده باشد، نصب‌کننده برای جایگزینی آن با ورود داخلی فام **تأیید جداگانه** می‌گیرد؛ بدون موافقت مسئول شبکه تأیید نکنید. در اجرای بدون تعامل، این تغییر فقط با `-UseFamAuthentication` مجاز می‌شود.

5. موفقیت فقط هنگامی اعلام می‌شود که اتصال واقعی **HTTPS با نام درست و همان گواهی انتخابی**، صفحهٔ مرکزی و مسیرهای API بررسی شده باشند. خطای نصب به عنوان موفقیت نشان داده نمی‌شود.

> در این انتشار اجرای معمول آفلاین است؛ پیش‌نیازها باید قبل از انتقال تکمیل شوند. حالت آنلاین فقط با انتخاب صریح `-Online` از PowerShell و نه از فایل CMD پیش‌فرض قابل انتخاب است.

## چه کارهایی خودکار انجام می‌شود؟

- کنترل اینکه IP واردشده واقعاً متعلق به همین سرور باشد؛ جلوگیری از نصب اشتباهی روی کامپیوتر کاربر.
- فعال‌سازی قابلیت‌های لازم IIS؛ نصب URL Rewrite و ARR در صورت فقدان؛ فعال‌کردن proxy در ARR.
- استفاده از Python x64 سراسری موجود 3.12 تا 3.14، یا نصب سراسری نسخهٔ پین‌شدهٔ 3.14.7؛ بررسی SHA256 و امضای ناشر نصب‌کننده‌های دانلودشده.
- ساخت محیط Python و نصب وابستگی‌ها؛ سرویس پشت IIS فقط روی `127.0.0.1:8765` اجرا می‌شود، نه روی شبکهٔ کاربران.
- ساخت/تنظیم وب‌سایت اختصاصی، اتصال HTTPS/SNI و اجرای backend با حساب محدود `LOCAL SERVICE` توسط Task Scheduler، با شروع خودکار پس از روشن‌شدن سرور.
- حفظ حساب‌ها/رمزهای موجود و دیتابیس موجود در مسیر نصب شناخته‌شده؛ بکاپ سازگار SQLite پیش از جایگزینی کد؛ تنظیم مجوز خصوصی داده و فقط خواندنی کد برای سرویس.
- ثبت بکاپ روزانه ساعت **23:00 به وقت خود سرور** و گرفتن بکاپ اولیهٔ تأییدشده؛ هر اجرا فایل تاریخ‌دار جدید می‌سازد و نسخه‌های قبلی را نگه می‌دارد.
- تولید بستهٔ گواهی عمومی و بررسی کلاینت. **هیچ کلید خصوصی صادر نمی‌شود.**

### مسیرهای پیش‌فرض

| مورد | مسیر/نام |
|---|---|
| برنامه | `C:\FAM\server` |
| ریشهٔ عمومی IIS، فقط همین پوشه | `C:\FAM\server\www` |
| دیتابیس | `C:\FAMData\fam.sqlite3` |
| گزارش نصب و نتیجهٔ HTTPS | `C:\FAMData\logs` |
| بکاپ‌ها | `C:\FAMData\backups` |
| بستهٔ عمومی کلاینت | `C:\FAMData\client-setup` |
| نتیجهٔ آخرین نصب | `C:\FAM\deployment.json` |
| وب‌سایت / App Pool | `FAM-Communication-02` / `FAM-Communication-02-Pool` |
| کارهای زمان‌بندی | `FAM-Central` / `FAM-Central-Backup` |

اگر Task قبلی به محل دیگری اشاره کند یا تنظیمات موجود به دیتابیس گم‌شده اشاره کنند، نصب متوقف می‌شود؛ به جای حساب‌ها و اطلاعات قبلی، دیتابیس خالیِ جایگزین نمی‌سازد. برای مسیر قبلی متفاوت، مدیر باید `-InstallRoot` صحیح را بدهد یا طبق راهنمای دستی مهاجرت کند. فایل مستقل HTML/حساب‌های محلی مرورگر **خودکار به دیتابیس سرور تبدیل نمی‌شوند**.

## روی کامپیوتر کاربران

با توجه به اینکه دسترسی شبکه قبلاً توسط مسئول شبکه فراهم شده، نیازی به درخواست دوبارهٔ همان مجوزها نیست. دو موضوع باقی می‌ماند:

1. نام `communication-02.toosbank.corp` باید روی کامپیوتر کاربران به `10.16.243.18` resolve شود. نصب‌کننده DNS سازمان یا فایل hosts کاربران را دست‌کاری نمی‌کند.
2. اگر گواهی self-signed هنوز مورد اعتماد کاربران نیست، مدیر **فقط پوشهٔ `client-setup`** را از مسیر بالا از راه مورد اعتماد به آنان بدهد؛ **کل `FAMData` را کپی/Share نکنید**. هر کاربر `TRUST-FAM.cmd` را با **همان حساب ویندوزی که مرورگر را باز می‌کند** اجرا کند، اثرانگشت SHA256 را با خروجی نصب روی سرور مقایسه کند و در صورت تأیید `YES` بزند. گواهی عمومی فقط به `CurrentUser\Root` همان کاربر اضافه می‌شود؛ Administrator لازم نیست. سپس DNS، HTTPS و دسترسی API کنترل و مرورگر باز می‌شود. گواهی صادرشده از CA سازمانی باید با روش عادی همان CA/GPO مورد اعتماد شود؛ اسکریپت، گواهی leaf سازمانی را خودکار به Root تبدیل نمی‌کند.

اگر گواهی فعلی از قبل در پنج سیستم مورد اعتماد است و نام هم درست resolve می‌شود، مرحلهٔ نصب اعتماد مجدد لازم نیست: کاربران همان **`https://communication-02.toosbank.corp`** را باز کنند. روی یک مرورگر دارای مخزن مستقل گواهی مانند بعضی تنظیمات Firefox، اعتماد باید طبق سیاست سازمان جداگانه بررسی شود. گزینهٔ «نادیده گرفتن خطای گواهی» راهکار این بسته نیست.

در نصب تازه، نام مدیر برنامه **`admin`** است؛ رمز در خروجی نصب نشان داده یا در ارتقا بازنشانی نمی‌شود. پیش از استفادهٔ عمومی رمز اولیه را عوض کنید و پنج حساب جداگانه با سطح دسترسی مناسب بسازید. داشتن حساب ویندوز/RDP به‌تنهایی حساب کاربری فام ایجاد نمی‌کند.

## آماده‌سازی آفلاین

روش جدید به Python روی کامپیوتر آماده‌سازی نیاز ندارد. [راهنمای Windows Server 2019 آفلاین](OFFLINE_SERVER_2019_FA.md) شامل لینک سه نصب‌کننده، ساختار پوشهٔ انتقال و منبع اختیاری Windows است. تمام wheelها در ZIP این انتشار موجودند. `PREPARE-OFFLINE.cmd` فقط روی کامپیوتر اینترنت‌دار اجرا می‌شود؛ `INSTALL-FAM.cmd` روی سرور.

## نکات عملیاتی مهم

- نسخهٔ ویندوز باید توان اجرای Python انتخابی و PowerShell 5.1 x64 را داشته باشد؛ سرورهای قدیمی‌تر از نسل Windows Server 2016 هدف این نصب‌کننده نیستند. نصب واقعی Windows/IIS هنوز در این محیط اجرا نشده است.
- نصب‌کننده دستور `iisreset` یا reboot خودکار اجرا نمی‌کند. با این حال نصب ماژول‌های مشترک IIS ممکن است روی دسترس‌پذیری دیگر سایت‌ها اثر بگذارد؛ نصب اولیه را در زمان نگهداری انجام دهید. تنظیم ARR proxy یک تنظیم سراسری IIS است.
- اگر Windows نیاز به reboot داشته باشد، نصب متوقف و درخواست اجرای مجدد پس از راه‌اندازی مجدد توسط مدیر می‌کند.
- به‌صورت پیش‌فرض فایروال/GPO و دسترسی‌های فراهم‌شده توسط مسئول شبکه تغییر نمی‌کنند. فقط اگر مسئول شبکه صریحاً `-AddFirewallRule` را انتخاب کند، قانون جدید HTTPS روی IP مشخص برای Domain/Private و LocalSubnet ساخته می‌شود؛ قانون موجود هم‌نام بازنویسی نمی‌شود. مجوزهای کاربران VLANهای دیگر تابع سیاست موجود شبکه‌اند.
- کد خروج `0`: HTTPS/API سرور و resolve نام از خود سرور موفق؛ `2`: HTTPS/API موفق ولی resolve نام نیازمند بررسی؛ `1`: نصب کامل نشده است. موفقیت سرور به تنهایی اثبات دسترسی پنج کامپیوتر نیست.
- در شکست، دیتابیس حذف نمی‌شود. اگر سایت تازه ساخته شده باشد متوقف می‌شود؛ مسیر/pool سایت قبلی تا حد امکان برگردانده می‌شود. این یک rollback کامل Windows/گواهی/تمام تغییرات IIS نیست؛ بکاپ تنظیمات IIS و گزارش‌ها برای بررسی مدیر باقی می‌مانند.
- بکاپ‌ها خودکار حذف نمی‌شوند؛ ظرفیت دیسک را کنترل و یک نسخهٔ محافظت‌شده در دیسک/سرور دیگری نگه دارید. کپی عادی فایل دیتابیس فعال جای SQLite backup API را نمی‌گیرد.
- AppLocker/WDAC/GPO محدودکننده یا نصب Feature بدون فایل منبع، ممکن است نیازمند اقدام مدیر باشد؛ سیاست سازمان دور زده نمی‌شود.
