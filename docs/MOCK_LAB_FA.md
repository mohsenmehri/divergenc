# راهنمای آزمایشگاه «سوئیچِ آزمایشیِ مجازی» (Mock) — تستِ نرم‌افزار فام بدونِ تجهیزِ واقعی

> **جمع‌بندی سریع:** چون تصویرِ IOL (لایسنس CML) در دسترس نیست و تجهیزِ یدکی هم نداریم، یک «سوئیچِ آزمایشیِ مجازی» می‌سازیم: نرم‌افزارِ تستیِ خودمان که مثلِ سوئیچِ `WS-C2960-24TT-L` از SSH جواب می‌دهد. با آن، کلِ مسیرِ نرم‌افزار را در **محیط آزمایشگاهی** تست می‌کنیم و سپس (مرحلهٔ ۷) با تجهیزِ واقعی به محیطِ اصلی می‌رویم.

## ۰. این ابزار چیست و چه نیست؟

- ✅ **چیست:** نرم‌افزارِ تستیِ خودِ پروژهٔ فام (در `lab/mock/` مخزن) که روی FAM-Ubuntu اجرا می‌شود و از SSH همان خروجی‌های IOS را می‌دهد (`show interfaces status` / `show interfaces description` / `show version`).
- ❌ **چه نیست:** تصویرِ IOS سیسکو نیست؛ هیچ کدِ سیسکویی ندارد؛ جایگزینِ «پذیرشِ نهایی روی سخت‌افزارِ واقعی» (مرحلهٔ ۷) نیست؛ هرگز در بستهٔ مشتری نمی‌رود.
- 🎯 **چه چیزی را تست می‌کند:** ورود SSH، تأییدِ کلیدِ میزبان، رمزِ فقط-RAM، «فقط وضعیت پورت‌ها»، «بررسی تجهیزات»، «نمایش توضیحات پورت‌ها» (با نمایشِ `[REDACTED]`)، «رفع خطای پورت با تأیید» (بازیابیِ err-disabled)، مجوزها و مسیرهای خطا.

**همهٔ دستورهای این راهنما در ترمینالِ «FAM-Ubuntu» (اوبونتو) اجرا می‌شوند؛ مرورگر روی ویندوز است.** هیچ دستوری را روی ویندوز/PowerShell اجرا نکنید.

## ۱. پیش‌نیازها

- FAM-Ubuntu بالا، داکر سبز، ورودِ `admin` به برنامه (از مراحل قبل).
- دسترسیِ `sudo` روی FAM-Ubuntu.

> **دسترسیِ راحت‌تر (اختیاری): SSH از ویندوز به‌جای کنسولِ VMware**
>
> در PowerShell ویندوز فقط همین یک دستور را بزنید (بقیهٔ دستورها بعد از ورود، اوبونتویی است):
>
> ```powershell
> ssh mohsen@192.168.97.128
> ```
>
> - اگر پرسید `Are you sure you want to continue connecting?` → `yes` را تایپ کنید (تأییدِ اولین اتصال است؛ چیزی را غیرفعال نمی‌کند).
> - رمزِ ورودِ لینوکسِ کاربر `mohsen` را تایپ کنید (فقط تایپ؛ در چت ننویسید).
> - پس از ورود، پرامپتِ `mohsen@fam-lab:~$` = همان ترمینالِ اوبونتو؛ **همهٔ دستورهای این راهنما همین‌جا** اجرا می‌شوند.
> - اگر پیام `ssh is not recognized` گرفتید: تنظیمات ویندوز → Apps → Optional features → «OpenSSH Client» را نصب کنید.
> - برای قطعِ اتصال: `exit`

## ۲. گام ۱ — IP آزمایشیِ سوئیچ (ترمینال اوبونتو)

سوئیچِ آزمایشی IP مخصوصِ خودش را دارد: `192.168.97.140` (همان IP برنامه‌ریزی‌شدهٔ آزمایشگاه).

```sh
sudo ip addr add 192.168.97.140/24 dev ens33
ip a | grep 192.168.97
```

- خروجیِ موردِ انتظار: دو آدرس `192.168.97.128/24` و `192.168.97.140/24`.
- ⚠️ این دستور موقتی است؛ اگر VM ری‌استارت شد، دوباره اجرا کنید.

📷 اسکرین‌شاتِ خروجی را بفرستید.

## ۳. گام ۲ — دانلود و نصبِ ابزار (ترمینال اوبونتو)

```sh
sudo mkdir -p /opt/fam-mock
sudo curl -L -o /opt/fam-mock/mock_switch.py https://raw.githubusercontent.com/mohsenmehri/divergenc/arena/06b5f68a-divergenc/lab/mock/mock_switch.py
sudo chmod 755 /opt/fam-mock/mock_switch.py
python3 -m py_compile /opt/fam-mock/mock_switch.py
```

- آدرسِ داخلِ بلوک را **چشمی** تطبیق دهید (آدرس‌ها گاهی در چت خراب می‌شوند).
- دستورِ آخر اگر چیزی ننویسد یعنی فایل سالم است. ✅

## ۴. گام ۳ — کاربرِ «سوئیچ» با رمزِ مستقلِ آزمایشگاهی (ترمینال اوبونتو)

```sh
sudo adduser --gecos "" mocksw
```

- در پرامپتِ `New password` یک **رمزِ مستقلِ آزمایشگاهی** تایپ کنید (نه رمزهای سازمانی!) و آن را **هیچ‌جا ننویسید** — نه در چت، نه در فایل، نه در اسکرین‌شات.
- این همان رمزی است که بعداً در برنامه («ورود حساب تجهیزات») تایپ می‌کنید و فقط در RAM می‌ماند.

📷 فقط پیام دهید «ساخته شد» (از پرامپتِ رمز اسکرین‌شات نگیرید).

## ۵. گام ۴ — معرفیِ mock به sshd (ترمینال اوبونتو)

هر خط را جدا جدا اجرا کنید:

```sh
echo "Match User mocksw" | sudo tee /etc/ssh/sshd_config.d/mocksw.conf
echo "ForceCommand /opt/fam-mock/mock_switch.py" | sudo tee -a /etc/ssh/sshd_config.d/mocksw.conf
echo "PasswordAuthentication yes" | sudo tee -a /etc/ssh/sshd_config.d/mocksw.conf
echo "PubkeyAuthentication no" | sudo tee -a /etc/ssh/sshd_config.d/mocksw.conf
echo "DisableForwarding yes" | sudo tee -a /etc/ssh/sshd_config.d/mocksw.conf
echo "Match all" | sudo tee -a /etc/ssh/sshd_config.d/mocksw.conf
sudo sshd -t
sudo systemctl reload ssh
```

- `sudo sshd -t` اگر چیزی ننویسد = پیکربندی سالم است. ✅ (هر پیامِ خطا را بفرستید.)

📷 اسکرین‌شاتِ خروجیِ `sudo sshd -t` و `sudo systemctl reload ssh`.

## ۶. گام ۵ — تأییدِ کلیدِ میزبان (همان تشریفاتِ همیشگی — هرگز بدونِ تطبیق)

مثلِ تجهیزِ واقعی: اول «حقیقت» را از خودِ سیستم می‌خوانیم، بعد اثرانگشتِ اعلام‌شده از شبکه را با آن تطبیق می‌دهیم، و فقط اگر یکی بودند ثبت می‌کنیم.

```sh
ssh-keyscan 192.168.97.140 > /tmp/mock-key.txt
ssh-keygen -lf /tmp/mock-key.txt
sudo ssh-keygen -lf /etc/ssh/ssh_host_rsa_key.pub
sudo ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub
sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

- سه خطِ آخر (اثرانگشت‌های واقعیِ سیستم) باید **دقیقاً** در خروجیِ خطِ دوم (اسکنِ شبکه) دیده شوند. اگر حتی یکی نبود، ادامه ندهید و اسکرین‌شات بفرستید.
- ✅ اگر تطبیق دادند، حالا ثبت کنید:

```sh
cat /tmp/mock-key.txt >> ~/FAM-Linux-Lab/data/equipment_known_hosts
```

📷 اسکرین‌شاتِ هر دو خروجی (اسکن و اثرانگشت‌ها).

## ۷. گام ۶ — تستِ دستی (اختیاری ولی مفید)

```sh
ssh -o StrictHostKeyChecking=yes -o UserKnownHostsFile=$HOME/FAM-Linux-Lab/data/equipment_known_hosts mocksw@192.168.97.140
```

- رمزِ آزمایشگاهیِ `mocksw` را تایپ کنید؛ باید پرامپتِ `MOCK-2960#` را ببینید.
- این دستورات را امتحان کنید و سپس `exit`:

```sh
show interfaces description
show interfaces status
```

📷 اسکرین‌شاتِ خروجیِ `show interfaces description`.

## ۸. گام ۷ — ثبتِ «سوئیچِ آزمایشی» در فام (مرورگرِ ویندوز → `http://192.168.97.128`)

1. «مرکز تجهیزات» → «دسته‌بندی‌ها»: اگر نیاز بود «مدیریت دسته‌های تجهیزات» — نوعِ تجهیز: «سوئیچ»، مدل: «2960» (از قبل در کاتالوگ هستند).
2. «افزودن تجهیز»:
   - نام: `sw-mock-1`
   - میزبان (IP): `192.168.97.140`
   - نوع: «سوئیچ» — مدل: «2960» — منطقه/محل: هر موجود (مثلاً منطقه ۱ / ساختمان مرکزی فام)
3. ذخیره.

📷 اسکرین‌شاتِ ردیفِ ساخته‌شده.

## ۹. گام ۸ — اولین بررسیِ فقط‌خواندنی 🎯

1. دکمهٔ «ورود حساب تجهیزات» → نام کاربری: `mocksw` → رمز: همان رمزِ آزمایشگاهی (فقط تایپ؛ در RAM می‌ماند).
2. دکمهٔ «نمایش توضیحات پورت‌ها» → جدولِ توضیحاتِ پورت‌ها:
   - باید `FastEthernet0/1` تا `0/24`، `GigabitEthernet0/1-2` و `Vl1` دیده شوند.
   - ردیفِ `FastEthernet0/11` باید `[REDACTED]` نشان دهد (توضیحِ حساسِ عمدی — نمایشِ قابلیتِ امنیتیِ محصول).
3. دکمهٔ «بررسی تجهیزات» → وضعیتِ پورت‌ها + پورتِ خطادارِ `Fa0/3` (IP-Phone-1).

📷 اسکرین‌شاتِ هر دو.

## ۱۰. گام ۹ — دموی «رفع خطای پورت با تأیید» (اختیاری)

در «بررسی تجهیزات» پورتِ `Fa0/3` با وضعیتِ err-disabled دیده می‌شود؛ با تأییدِ شما، «رفع خطای پورت با تأیید» اجرا می‌شود (shutdown/no shutdown روی همان پورت) و در بررسیِ بعدی پورت سالم گزارش می‌شود. ✅

## ۱۱. عیب‌یابی سریع

| مشکل | احتمالاً کجاست؟ |
|---|---|
| پیام `sudo is not recognized` یا `grep` پیدا نشد | دستور را در PowerShell ویندوز زده‌اید؛ **همهٔ دستورهای این راهنما فقط در ترمینالِ FAM-Ubuntu (کنسولِ ماشینِ مجازی در VMware) اجرا می‌شوند** — نه در ویندوز |
| `connection_failed` / اتصال رد می‌شود | IP `.140` بعد از reboot پاک شده — گام ۱ را دوباره بزنید. یا `sudo ufw status` — اگر فعال بود: `sudo ufw allow from 172.17.0.0/16 to any port 22 proto tcp` |
| `authentication_failed` | نام کاربری/رمز اشتباه؛ رمز را با `sudo passwd mocksw` دوباره بگذارید |
| `host key verification failed` | کلید بدونِ تطبیق ثبت شده یا سیستم عوض شده؛ فایل `~/FAM-Linux-Lab/data/equipment_known_hosts` را بررسی کنید |
| «خروجی show int des قابل تأیید نیست» | خروجیِ mock خراب است — `python3 /opt/fam-mock/mock_switch.py` را دستی امتحان و اسکرین‌شات بفرستید |
| بعد از ری‌استارتِ FAM-Ubuntu، پورتِ `Fa0/3` دوباره خراب شد | طبیعی است؛ وضعیتِ mock در `/tmp` نگه داشته می‌شود و با ری‌استارت به حالتِ اول برمی‌گردد |

## ۱۲. یادآوریِ کوتاهِ قواعد

1. رمزِ تجهیز فقط هنگامِ ورود تایپ می‌شود؛ هرگز در چت/فایل/اسکرین‌شات نیاید.
2. کلیدِ میزبان همیشه با تطبیقِ اثرانگشت؛ هرگز `StrictHostKeyChecking=no`.
3. این ابزار تستی است و در بستهٔ مشتری نمی‌رود؛ **پذیرشِ نهایی روی سخت‌افزارِ واقعی (مرحلهٔ ۷)** انجام می‌شود.
4. فام هرگز `enable` / `write memory` ارسال نمی‌کند و mock هم این‌ها را قبول نمی‌کند.
